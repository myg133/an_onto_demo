## F-1 · ⭐ 真 M2 下**退出码是 0**，不是 3

Dev 自陈「退出码 3 是第二道闸」。**QA 实测证伪**：Rust 闭包**捕获环境变量**，
所以

```rust
emit_domain_text_with(&text.replace('\u{240A}', "\n"), |judged| { verify(&rv, &text) })
```

**就是 M2 本体**（编译通过、`grep -c '^error'` = 0）。
此时判据拿**未加工**那份 ⇒ 三道自检合法沉默 ⇒ `self_check_exit_code` 返回 `None` ⇒ **退出码 0**。

⇒ **挡住它的是 G-1，不是退出码政策。**

**问题**：`EXIT_POLICY` 说「0 = 干净」，而在真 M2 下 stdout 已被完全攻破、退出码**仍是 0**
⇒ **政策对 0 号码的描述在该场景为假。**

- 预期结果：要么让真 M2 下退出码**真的非 0**，要么**如实改写 `EXIT_POLICY` 对 0 的描述**
- ⚠️ 依据本会话反复出现的病：**信号不承载它声称的含义**
  （「读得到 ≠ 门禁会通过」的同族：现在是「**退出码 0 ≠ 干净**」）

## F-2 · 4 个 `same_binding` 站点的 **G-1 形同虚设**

shadowing 构造下 **G-1 五条全绿**（③ 只比词元，两边仍都叫 `json`），
真正判红的是端到端字节比对。

⇒ **防线完全落在 e2e 上，e2e 一旦被改就是零防线。**

- 预期结果：要么让 G-1 在这 4 处也有效，要么**如实登记「这 4 处 G-1 无判别力」**
- ⚠️ ⛔ **不许**把「e2e 抓到了」写成「G-1 抓到了」

## F-3 · 两处「无载荷面」**与代码不符**

Dev 登记「`ontology diff` / `proposal apply` 无文本载荷面」，
QA 实测 **`DiffItem.target` 来自快照 key、`before`/`after` 是原始 JSON，未转义流入 stdout**。

- 预期结果：修正登记，或给这两处**真的**加上覆盖
- ⚠️ 依据本项目已有的转义不变量（`escape_payload_text`）：**payload 文本不得原样进渲染**
  —— 若这两处是漏洞，那是**同一个不变量被绕过**

## F-4 · `to_regclass` 对**确实存在**的 schema 返回 `None`

QA 实测 2/2：对确实存在的 schema，`to_regclass(schema_name)` 返回 `None`，
而权威的 `pg_namespace` / `information_schema` 都返回 `Some`。
⇒ 「DROP 报成功但还在」那一格**永远不触发**。

**恰是 Dev 自己认定的「历史形状」没生效。**

- 预期结果：改用 `pg_namespace` / `information_schema` 查询
- ⚠️ **判别力自证**：构造「schema 确实还在」的复现，
  证明改后的检查**会红**（不然又是一条恒真空壳）
