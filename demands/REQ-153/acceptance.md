# 验收标准：REQ-153

## 一 · AC

### AC-001 · 三类缺口都能盘出来（用真实形状的账单）

- 输入：一份**真实形状**的「按产品汇总」账单（脱敏）+ 一份 `am-tencent.json` + 一份字典
- 断言：`missing_classes` 里有"轻量应用服务器"（金额 382.33、占比 14.96%）
- 断言：`classes_without_contract` 里有 `eip`（catalog 有、am 无）
- 判据：报告原文 + 三个数组条数

### AC-002 · 字典没声明的产品**不许静默丢**（R2）

- 账单里加一个字典里没有的产品 ⇒ 必须出现在 `unmapped_products[]` + 一条警告
- ⛔ 不许归到 `missing_classes`（那会诱导"自动建"），也不许消失
- 判据：一次

### AC-003 · `null` 是合法决策（R3）

- 字典里 `"NAT 网关": null` ⇒ **不进** `missing_classes`
- 报告里可在"已决定不建"单列，但不得计入缺口
- 判据：一次

### AC-004 · 排序与阈值

- `missing_classes` 按金额**降序**
- 最高占比 ≥ 2% ⇒ 退出码非 0；`--fail-threshold 50` ⇒ 退出码 0
- 判据：两条命令的退出码

### AC-005 · `contract_without_class` 是 P0

- 造一份指向不存在类的 mapping ⇒ 该数组非空 + 退出码非 0 + 报告里标 P0
- 判据：一次

### AC-006 · 只读（R1）

- 跑完之后：元数据库**无写入**（项目/版本数不变）、**无网络请求**（源库/云 API URL 指不存在也照跑）
- 判据：前后计数 + 一次"URL 指不存在主机"的跑法

### AC-007 · 无厂商分支（R6）

- `grep -riE 'tencent|aws|aliyun|BusinessCode' src/`（构建面新代码）⇒ 0
- 账单取值路径来自参数/声明
- 判据：grep（先贴红，再贴绿）

### AC-008 · 两种输出

- `--format md` ⇒ 人能直接看的 `gap-report.md`（含三张表 + 已决定不建）
- `--format json` ⇒ 上面的结构
- 判据：两份产物

### AC-009 · 不退化

- 全量测试三列 + 逐条归因；基线**含生成物**
- ⛔ 禁改四红线 / `tools.rs` / `guard()` / `property_filter.rs`；⛔ 新依赖
