## 事实基线（BA 已逐条核实，Dev 可复核可否定）

### ① 格式定义在 `src/extract/names.rs:27-37`

```rust
pub struct TableNames {
    pub agent: String,        // 谁产出的
    pub version: String,      // 改翻译就改它
    pub generated_at: String, // ISO-8601
    pub source: String,       // 源库标识
    pub names: HashMap<String, String>,  // 表名 → 中文名
}
```

未标 `deny_unknown_fields` ⇒ **多带字段是既有实践**：
committed 版 `table_names.json` 就带了一个 `_note`。这条是 AC-002 的可行性依据。

### ② `TableNames::load`（`:44-58`）只有三条校验，**任一条不满足 ⇒ 整张表 `bail`**

| 校验 | 失败后果 |
| --- | --- |
| `names` 非空 | 整份翻译表报废 |
| 中文名 `trim()` 后非空 | **整份**报废（不是丢一张表） |
| 中文名 ≠ 表名（大小写不敏感） | **整份**报废 |

⚠️ **这是个放大器**：一张表翻错 ⇒ 全部 91 张表都抽不出来。
所以「校验」不是收尾步骤，是**每条翻译都必须过的一道闸**。

### ③ 查不到中文名的表**静默消失**（`src/extract/propose.rs:369-374`）

```rust
let display_name = match entity_display_name(t, &names) {

```

只往 `stats` 塞一个计数，**没有 stderr、没有非零退出码**。
一次翻译覆盖率 80% ⇒ 客户视图少 18 个对象，而抽取器报「成功」。

## 要做什么

新增一个 bin：**`ontok-translate-names`**

```

可选：已有的翻译表（做增量）

```

## AC-001 · 产出必须能被 `TableNames::load` 原样接受，**不得自己写一份校验**

- 生成器**不许**自己实现「空名 / 同名 / 空表」三条检查，必须调 `TableNames::load`
  （理由：校验规则有两处真身——`load` 与 `usable_as_human_name`——复制即漂）
- **构造样本自证**（放 `.review-workspace/req090/`，⛔ 不许进 `tests/` 夹具）：
  制造三种坏产出，实测 `load` 各自 `bail` 且错误信息**指名道姓**是哪张表：

| 注入 | 期望 |
| --- | --- |
| 中文名 = 表名 | bail，错误含该表名 |
| 中文名 = `"   "` | bail，错误含该表名 |
| 全部表都没翻 | bail「翻译表是空的」 |

- ⛔ **编译失败不算执行**。每条变异必须给 **三元组**（纪律 G）：
  变异期二进制 sha256 + patch 哈希 + 运行条数。只给二进制路径名的，视同没交。

## AC-002 · 覆盖率必须**可数**，不许「尽力而为」

- 输出**必须**同时给两处，缺一不可：
  1. stdout / stderr 的一行汇总：`translated N / total M`
  2. 机器可读的**缺口清单**：未翻译表名数组 + 已从 schema 消失的表名数组
- 缺口清单**用承载形式由 Dev 选**（`TableNames` 的额外字段 / sidecar 文件），但必须满足：
  - ⛔ **不得**为了承载它去改 `TableNames` 结构定义（`names.rs` 本 REQ 只读，见 AC-006）
  - 缺口必须能被人和脚本同时读到；**不得**只能靠人眼看日志
- **构造样本自证**：造一份 5 缺 2 的 schema，实测两条通道都报出 2，且**退出码语义能区分**
  「全覆盖」与「有缺口」——说清你选的是哪种（硬失败 vs 警告）并给理由。

## AC-003 · 增量语义：**新表补、旧表留、删表显式**

一条翻译是**人工确认过的知识资产**，不是机器输出。生成器一跑就把人改过的名字冲掉，
比不生成还糟。所以：

| 情形 | 要求 |
| --- | --- |
| schema 新增的表 | 翻译并**新增** |
| schema 里还在的旧表 | **默认原样保留**，⛔ 不覆盖 |
| 显式要重翻某张 | `--overwrite <表名>`（可重复），或 `--regenerate-all` |
| schema 里**已消失**的表 | 进缺口清单（AC-002 的第二个数组），⛔ **不得**静默从 `names` 里删掉 |

⚠️ 最后一行是本 AC 的重点：静默删除等于「这条业务对象从世界上消失了，且没人知道」。
`--regenerate-all` 下已消失的表**同样**只进清单、不删——删除必须是人的显式动作。

**构造样本自证**：3 旧 + 2 新 + 1 已删的 schema，跑两遍（第二遍改 schema），
实测：旧 3 条逐字节未变、新 2 条已进、已删那条仍**在** `names` 里**且**出现在清单中。

## AC-004 · 溯源字段**不得是占位**

REQ-059 的教训：`--agent` 曾硬编码 `"mcode-agent"`、`--agent-version` 默认 `"unknown"`
还**被翻译表的版本号顶替** ⇒ 产物里记着一个与执行者无关的自证假溯源。
字段名还与「翻译表由谁产出」长得几乎一样，格外误导。

因此本 AC：

- ⛔ `agent` **不得**是硬编码常量；必须是**这次真正跑起来的实现**的自报身份
  （对齐 `ontok-propose` 的 `INPROC_EXECUTOR_ID` 口径）
- ⛔ `version` **不得**从别处借（`TableNames.version` 就是本字段，`load` 不会替它填，
  但要防你为了省事去读旧表的 `version` 当新表的 `version`）
- `generated_at`：ISO-8601，取真实生成时刻
- `source`：⚠️ **SchemaReport 里没有库名**，只有 `schema`（pg schema 名，如 `public`）
  （已核 `introspect.rs:73-88`）⇒ ⛔ **不得**编一个看起来像库名的默认值。
  要么由 `--source` 显式传入（无默认，缺则报错），要么就写 `schema` + `table_count`
  这种**确实是事实**的描述。committed 真表里的 `source` 是
  `"<示例 schema> (public schema, 91 tables)"` 这种人写的自由文本
  ⇒ 参考它的**信息密度**，不要抄它的**不透明**。
- **自证**：把 `agent` 换成硬编码常量跑一次，`grep` 产物 + `git diff` 应立刻看出不一致。

## AC-007 · 中文名质量：只查**退化**，不查**雅俗**

`usable_as_human_name`（`view.rs:656-665`）的规则是「**词元相等**」，不是子串包含。
CJK 字符在 Rust 里 `is_alphanumeric()` 为真 ⇒ `客户订单` 是**一个**词元，不会被切碎。
所以：

- ⛔ **不许**加「中文名不得包含其他表名」的检查（会误杀绝大多数正常翻译）
- ✅ **只**加一条退化自检：中文名经 `tokenize` 后，**任一词元恰好等于某个实体 key**
  ⇒ 标出来（典型触发场景：中英混排 `订单 Order` 在某库恰有 key `order` 时）
- ⚠️ **翻译得好不好无法自动判定** ⇒ 交付时必须给出一份**人工可抽查的清单**
  （表名 + 中文名 + 列注释摘要），不许只交「已生成 91 条」

## AC-008 · 翻译表是**程序运行时产物**，不是人手写出来的文件

> 2026-10-12 负责人裁定原文：「**这个工作是程序的工作，不是你的工作。翻译也是程序的一部分。**」
> 本 AC 即该裁定的落地。此前 BA 曾把「生成的翻译表放哪 / 是否入库」当成待拍板项 ——
> **那个问题本身就问错了**：手工路径才需要决定文件放哪；走程序路径时它压根不是仓库资产。

因此：

- ⛔ 生成器**不得**默认写入任何**受版本控制**的路径（特别是 `src/extract/table_names.json`）
  —— `--out` **必填**，无默认
- ⛔ 生成器**不得**修改仓库内任何既有文件；只允许新建 `--out` 指定的那一个文件
- ✅ 必须**非交互可运行**：不读 stdin、不依赖 TTY、不弹确认 —— 能被脚本 / CI 无人值守调用
- ✅ 失败必须是**非零退出码 + stderr 可读信息**，不得靠「产物里少几条」表达失败（呼应 AC-002）
- ✅ `--help` 必须能完整说明输入格式、输出格式、增量语义（AC-003）与所需环境变量**名**
  （⛔ 不得在 help 或任何输出里回显 key 的值）

## AC-009 · 关键性质：翻译**质量**不由本工具判定，但**可用性**必须由本工具保证

拆开两件事，别混：

| 性质 | 谁负责 | 本 REQ 的义务 |
| --- | --- | --- |
| **可用性**（能不能被 `load` 接受、会不会静默丢表） | **本工具** | AC-001 / AC-002 / AC-003 全覆盖 |
| **质量**（译得准不准、客户认不认） | **人** | AC-007 交人工抽查清单；**登记为限制 L-1** |

⛔ **不得**用「质量无法保证」当理由弱化可用性义务 —— 「保证不了译得好」
不等于「可以交一份 60 条对 31 条的表还报成功」。
