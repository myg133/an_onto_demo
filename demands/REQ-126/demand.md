# 需求：REQ-126 · 客户门户（租户锁死，只能问预置问题）

## 基本信息

| 项 | 值 |
| --- | --- |
| 需求编号 | REQ-126 |
| 优先级 | **P1** |
| 状态 | 进行中 |
| 基线 | `develop`（REQ-125 合并后） |
| 前置 | REQ-122（查询注入）、REQ-123（token→租户）、REQ-125（前端形态） |

## 与 REQ-125 的根本区别

| | REQ-125 内部工作台 | **REQ-126 客户门户** |
| --- | --- | --- |
| 用户 | FDE / 实施 | **客户本人** |
| 凭证 | admin token | **portal token（绑定一个租户）** |
| 能切项目/版本 | ✅ | ⛔ **不能，一个进程只服务一个项目版本** |
| 能写 | ✅（评审/应用/冻结/声明） | ⛔ **完全没有写** |
| 能写 SPARQL | ✅ | ⛔ **不能，只给预置问题** |
| 能看到别人的数据 | 调试时可以（审计） | ⛔ **结构上不可能** |

**两者必须是两个命令、两套凭证、两个服务**——不是同一个页面的两个角色。

## 为什么客户不能自由写 SPARQL

| 原因 | 说明 |
| --- | --- |
| 能力 | 客户不会写 SPARQL |
| 安全 | 自由查询 = 自由消耗；一个 `ORDER BY` 全表就能拖垮服务 |
| **诚实** | 客户要的是「我的费用多少」，不是「给我查询器」 |

⇒ 门户只提供**预置问题卡片**，每个问题的 SPARQL 由**声明文件**给出，参数（租户）由服务端注入。

## 形态

```
ontok portal serve --bind 127.0.0.1:8900 --tokens portal-tokens.json \
    --project <P> --version <V> --schema schema.json \
    --policy query-policy.json --questions portal-questions.json
```

### 预置问题声明 `portal-questions.json`

```json
{
  "version": "1.0.0",
  "reviewed_by": "业务负责人@2026-10-23",
  "questions": [
    { "id": "monthly_deduction",
      "title": "我本月扣了多少（按币种）",
      "sparql": "SELECT ?cur ?amount WHERE { ?d :deductions__currency ?cur . ?d :deductions__deduction_amount ?amount }",
      "note": "按扣费明细汇总；不含子账号产生的部分" }
  ]
}
```

| 规则 | 说明 |
| --- | --- |
| 一个问题一条 SPARQL | ✅ 可评审、可测试 |
| **参数只能来自 token 的租户** | ⛔ 不许问题自带「查谁」 |
| 启动时**逐题校验** | 问题涉及的表必须在 policy 里登记为租户表或公共维度；否则**拒绝启动**并点名 |
| `reviewed_by` 必填 | 问题本身是业务口径，必须有人签 |

## 范围

### 做

1. `portal serve`（独立命令、独立凭证、独立端口）
2. **页面**：问题卡片列表 → 点开看结果（表格 + 说明 + 覆盖警告）
3. **只提供 `GET /`（壳）与 `POST /q/<id>`（执行一个问题）**
4. 结果区**必须显著展示**：`warnings`（可能漏数据）、`truncated`、数据说明（哪些对象参与）
5. 启动时校验问题声明（表/列存在、租户覆盖确定、`reviewed_by` 非空）
6. 审计：每次问题执行一行

### 不做

- ⛔ 不做自由 SPARQL 入口
- ⛔ 不做任何写操作（评审/应用/冻结/声明编辑）
- ⛔ 不做项目/版本切换（进程级固定）
- ⛔ 不暴露 `sql_echo`（客户不需要 SQL；技术细节不外露）
- ⛔ 不引前端框架

## 关键裁定

| # | 问题 | 裁定 |
| --- | --- | --- |
| R1 | 租户来源 | **只能来自 portal token**；⛔ 请求体/URL 不许带 tenant |
| R2 | 问题声明缺失/非法 | **拒绝启动**（fail-closed），点名哪一条 |
| R3 | 问题涉及未登记的租户表 | **拒绝启动**（与查询期 fail-closed 一致，但更早） |
| R4 | 结果说明 | 必须说清「这是哪些业务对象的数据」+ 覆盖范围；⛔ 不暴露表名/列名/SQL |
| R5 | 页面壳 | **零数据**（不含项目名、对象名、问题文案也不预置在壳里——问题列表走 API） |
| R6 | 与 REQ-125 | 复用其**登录态与页面样式**，但**完全独立的服务**（不共享进程/凭证/路由） |

## 风险

| # | 风险 | 缓解 |
| --- | --- | --- |
| 1 | 门户被当成查询器滥用 | 只允许预置问题；参数固定；行数上限 |
| 2 | 问题声明写错导致查错数 | 启动校验 + `reviewed_by` + 问题里 `note` 写明口径 |
| 3 | 客户看到技术细节 | R4：只渲染业务名，不渲染 SQL/表名列名 |
| 4 | 与工作台混用凭证 | 两套 token 文件、两套 `kind`，加载期互斥（复用 REQ-124 的 kind 校验） |
