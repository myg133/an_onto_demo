# 验收标准：REQ-126 · 客户门户

> **一句话**：客户只能问**被审过的问题**，只能看到**自己的数据**——**结构上做不到别的**。

## 一 · AC

### AC-001 · 租户锁死

| 攻击 | 期望 |
| --- | --- |
| 请求体/URL 带 `tenant` | **400/403**（不接受，不是忽略） |
| A 的 token 查（正常） | 只返回 A 的数据 |
| A 的 token 试图查 B（任何方式） | **0 行**，且无法表达 |
| 无 token / 错 token | 401 |

- 判据：用两个真实租户对拍，**交集为空**
- 判据：代码里没有「从请求读取 tenant」的路径（grep + 代码审查）

### AC-002 · 只有预置问题

- 端点只有：`GET /`（壳）、`GET /api/questions`（列表）、`POST /q/<id>`（执行）、`GET /api/health`
- 判据：**没有** `/api/sparql`（自由查询）入口
- 判据：`POST /q/<未知id>` ⇒ 404 + 可读
- 判据：请求体里带 `sparql` 字段 ⇒ **被忽略或拒绝**（⛔ 不许执行）

### AC-003 · 启动校验（fail-closed）

| 情形 | 期望 |
| --- | --- |
| 问题声明的 `reviewed_by` 为空 | **拒绝启动** 并点名 |
| 问题涉及 policy 里未登记的表 | **拒绝启动** 并点名问题 id + 表名 |
| 问题里的属性在目录里不存在 | **拒绝启动** 并点名 |
| 一条问题都合法 | 启动成功 |

- 判据：四种各一次

### AC-004 · 结果必须解释清楚

- 每个结果区必须显示：
  1. **数据说明**：涉及哪些业务对象（用**业务名**，不是表名）
  2. **覆盖警告**：若涉及 `coverage: main_only` 的表 ⇒ 显著提示（如「不含子账号数据，金额可能偏低」）
  3. `truncated` 若为真 ⇒ 明确提示
- 判据：查 `deductions` 相关问题 ⇒ 警告可见
- ⛔ 不显示 `sql_echo`、表名、列名、属性 IRI

### AC-005 · 页面壳零数据

- `GET /` 响应体里 grep：项目名 / 版本号 / 对象名 / 问题标题 ⇒ **0 命中**
- 判据：问题列表走 `GET /api/questions`（带 token），不在壳里预置

### AC-006 · 凭证隔离

- portal token 调不了 console 的管理端点（不同服务，且 kind 不同）
- console 的 admin token 调不了 portal（401）

### AC-007 · 零依赖与体积

- 页面内 `<script src=` / `<link href=` / `https://` / `@import` **全 0**
- 单文件 < **120 KB**
- CSP / nosniff / no-referrer 三个头都在

### AC-008 · XSS

- 对象名/说明/错误信息一律 `textContent`
- 判据：构造含 `<img src=x onerror=alert(1)>` 的对象名 ⇒ 显示原文，不执行

### AC-009 · 审计

- 每次问题执行一行：`时间 / token 摘要 / 问题 id / 租户 / 行数 / 耗时 / code`
- 判据：⛔ 无 token 明文；⛔ 无 SQL

### AC-010 · 限额

- 行数上限（token 级）、超时；超限 ⇒ 截断或错误，页面可见

### AC-011 · 不退化 / 零依赖

| 项 | 约束 |
| --- | --- |
| ⛔ 禁改 | 四红线 + `tools.rs` + `guard()` + `property_filter.rs` + `console` 路由 + `query` 路由 |
| ⛔ 禁 | 删测试、`#[ignore]`、放宽断言、新增依赖 |
| 基线 | REQ-125 合并后的 lib/doc 数字 |
| 出口 | 门户页面与 API 登记进 `OUTLETS`（内部轨） |

## 二 · 纪律

- **H** 门户执行查询必须复用 REQ-122 的 `run_query`（同一注入逻辑），⛔ 不许另写
- **G** 变异：让门户接受请求体 tenant / 开放自由 SPARQL / 页面壳塞项目名 ⇒ 每条必须被抓
- **S** AC 也会错，发现直接说
