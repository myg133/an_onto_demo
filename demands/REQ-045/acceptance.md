## 背景：为什么这条优先级最高

REQ-044 封口了 5 条已知洞（F-1 / F-3 / F-4 / C4 / F-5），
理由都是「触发它们需要**刻意构造不自然的源码形状**⇒ 是决策不是待办」。

但 QA 随后撞出一条**比那五条都严重**的洞，它**推翻了上面那条判据本身**：

> **判据检查的是过期源码，却看起来完全在工作。**

> **⚠️ 2026-10-09 订正**：AC-001 初稿写的机制「**`include_str!` 不建立 cargo 的文件依赖追踪**」
> **是错的**，Dev 实测 + QA 独立复现 + BA 复核三方一致推翻。实测工具链 **cargo 1.98.1 / rustc 1.98.1**：
> 旧版判据的 dep-info **精确含 5 个文件**（`test_connect_retry.rs` / `test_db.rs` /
> `common/mod.rs` / `src/db/pool.rs` / `src/db/apply.rs`），**cargo 会按 dep-info 重编译**。
> **真实机制**：内容**在编译那一刻固化进二进制** —— 只要**直接执行已编译二进制**（不经 cargo），
> 就永远拿不到编译之后的改动。
> ⚠️ **不同 cargo 版本行为可能不同**，本条结论**只对实测的 1.98.1 成立**，不得写成无条件命题。
>
> 决定性 A/B（同一份已变异的 `test_db.rs`、**直跑二进制不经 cargo**）：
> 旧版 `include_str!` **12 passed / 0 failed（盲）**、`read_source` 新版 **11 passed / 1 failed（看见）**。
> ⚠️ **经 cargo 的那条自证不具区分力** —— 新旧**都**是 11/1（旧版靠 dep-info 重编译重新内嵌）。
>
> **实证事故**（QA 报告 + BA 复核）：

| 观察 | 内容 |
| --- | --- |
| develop 工作区 | `git status` **空**，裸 grep `rawconnect` **计数 0** |
| 判据输出 | 报出一段**只在 QA 探针污染过的文件里才存在**的 `rawconnect` 代码并红 |
| 强制重编译后 | `touch tests/test_connect_retry.rs` ⇒ **12 passed / 0 failed** |

**加重因素（BA 自查出的操作习惯问题）**：BA 用 `target` 符号链接让子 agent 的 worktree
与 develop 共享构建产物；两侧 `CARGO_MANIFEST_DIR` 不同却 **fingerprint 互相覆盖**
⇒ 跨 worktree 复用了别的目录编译出来的二进制。

**为什么这条最要紧**：那五条洞都要**刻意构造**才能触发；
**这条是日常改代码就会踩到** —— 任何人改 `test_db.rs`，判据都不会更新，且**一声不响**。

## AC-001 · 判据必须读当前源码（**核心**）

- 预期结果：判据改为**运行时读文件**（`std::fs::read_to_string` + `env!("CARGO_MANIFEST_DIR")`）
  或等效的、**每次运行都取当前内容**的方案
- 类型：测试有效性
- **判别力自证（必做）**：构造一条变异 —— 改 `tests/test_db.rs`，**只跑 `test_connect_retry`**
  （不 touch 判据文件本身），验证判据**立刻看到新内容**并据此判红/判绿。
  - **若仍然看不到新内容 ⇒ 本条不通过**
  - 报告须说明**改了什么**、**判据的反应是什么**（红色 / 绿色 / 报错）

> ⚠️ **不要用 `build.rs` + `cargo:rerun-if-changed`** 作为主方案 ——
> 对「测试里读另一个测试文件」这个用例偏重。若你认为 `build.rs` 更合适，先说明理由。

## AC-002 · 读文件失败必须 fail-closed

- 预期结果：路径不存在 / 读不到 ⇒ **报错并指出是哪个路径**，**不是**静默跳过
- 类型：架构
- ⚠️ **理由**：`include_str!` 的一个隐性好处是「文件不在就编不过」。
  改成运行时读之后这个保证消失了，**必须显式补回来**，
  否则「文件改名了判据悄悄不检查」会比现在更糟。

## AC-003 · 修正 3 条失真封口论证（**必交，代码行为不动**）

QA 实测推翻了 REQ-044 封口里的三条论证。**代码行为本身无误，要改的是「为什么接受」这段文字**：

| 洞 | 现文字的问题 | QA 的实测证据 |
| --- | --- | --- |
| **F-1** | 代码 `:1065` 断言「raw string 里的 `for` / `sleep(` **不会露出来**」 | **P7d 证伪**：raw string（引号偶数）里的 `sleep(` **泄进屏蔽视图** ⇒ 判绿，而真身是 **3 次尝试、零退避** ⇒ **真假绿**。另 **P7**（引号奇数）会让扫描器**跨行失步直接 panic** —— 方向保守但**失败模式失控** |
| **F-4** | 「修复需**完整 Rust 解析器**」 | **成本论证错误**：本 PR 自己刚在 `all_retry_loops` 用「枚举全部不取第一个」，同手法套 `fn_body` 仅**十余行** |
| **C4** | 「`_` 前缀豁免是刻意设计，允许 `_unused` 惯用法」 | **描述被缩小 + 与代码路径对不上**：代码 `:776` 是 `before.ends_with("_")`，豁免**任何** `_` 结尾前缀（含 `raw_connect`）；而 `connect_sites` 只找 `connect(`，两者对不上 |

- 预期结果：三段文字**改写成实测事实**，每条附 QA 的证据出处
- 类型：文档正确性
- **不通过的处理**：文字不改对 = 本需求没做到。**封口声明的作用是让下一个人做对决策，
  失真的封口比没有封口更糟。**

## AC-004 · 封口判据改成二维

REQ-044 用的「需要刻意构造 ⇒ 是决策」**漏了成本维度**。
QA 指出反例：**C4 只要把 helper 叫 `raw_connect`（日常命名）就不满足「刻意构造」，
却被算作决策**。

- 预期结果：改成二维判据「**自然度 × 修复成本**」，
  并用它**重新评估**那 5 条（结论可以与之前相同，但**必须是用新判据推出来的**）
- 类型：文档正确性

## 环境事实

- 共享集群 DB 很慢：`SELECT 1` p50 实测 **133~161 ms**；总连接常驻 **32~38 / 100**
- **先探延迟再判断测试慢不慢**；复现率随负载浮动，**不声称稳定值**
- 报告把「代码失败」与「环境类失败」**分开写**
- ⚠️ **运行期判据与环境类失败严格二分** —— 环境失败绝不能冒充「杀死」
- ⚠️ **`.env` 里库名就是 `notol`**，忘了替换成 `ontol` 会让 DB 测试秒败、
  且症状像「集群故障」—— 本会话已有 Dev 与 QA 各踩过一次
- 本机**没有 `psql`、没有 psycopg**
- 共享本体库**禁 DELETE / TRUNCATE / 清空表**；源库只读
- 口令只走环境变量，**绝不写进报告**；⚠️ **不要 `echo` 连接串**
