## N-3 的关键：假阳性从哪来

原判据是「在 `merged.json` 里 grep 不到被排除的名字」。真实 fixture 上它**必假红**：

```
"quote": "## 未来规划\n\n平台计划在下一财年支持积分转赠"
         ↑ 这是已并入条目「客户」的 doc_evidence 引文，不是条目
```

新判据按**身份**判：

| 身份 | 比法 |
| --- | --- |
| `Concept(name)` | `target` / `display_name` / `key` **整值相等** |
| `Relation{subject,predicate,object}` | 两端**整值相等** ∧ `semantic` **整值相等** ∧ 方向可反 |

### 绿红成对（缺一不可）

```
[绿] 合法边「套餐退款→客户」(semantic=退款) ⇒ 判据结论 []（不该判成泄漏）
[红] 塞一条身份相同的 relation 条目        ⇒ 判据点名「第 6 条 … 相同」
```

而且**绿判据自己有牙**：把判据临时改回 `contains` ⇒ 绿判据立刻红
（`套餐退款` 含 `退款`，端点超串被误判成泄漏）。

> 只做红会过严（把合法边当泄漏），只做绿会放水。**两条一起才说明判据精准。**

## `signed_at_source` 三值

| 值 | 含义 | 可信度 |
| --- | --- | --- |
| `arg` | `--at` 给的 | **声明**（可复现） |
| `system` | 本次运行的系统时钟 | **记录**（不可复现为同一秒） |
| `legacy` | 老产物没有这一栏 | 读回按缺省处理，⛔ **不补写**（补写=改写历史） |

判据还额外查「`system` 时间落在本次运行窗口内」，防「恒写 system + 写死时间」。
