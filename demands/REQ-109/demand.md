# 需求：REQ-109 · AI 语义项接入（带指纹缓存与预算闸）

## 基本信息

| 项 | 值 |
| --- | --- |
| 需求编号 | REQ-109 |
| 优先级 | **P1**（在 REQ-108 的确定性基线上加语义判断） |
| 状态 | 草稿 |
| 前置 | **REQ-108 必须已合并**（评分卡的 `semantic_fit` 权重位、`confidence` 结构、自证链校验） |
| 来源 | 2026-10-21 离线对照实验：AI 对 28 条问题关系给出 11 条可执行修正，**被采样推翻 0 条** |

## 需求描述

### 现状：AI 在代码里存在，但跑不起来

`src/agent/llm/` 已实现（REQ-034），但它只能声明 `reports_usage`，**不能**声明 `produces_proposal`——因为它提供不了 `property.origin` / `rejected_comments` 这类溯源字段，而 `stats.json` 是验收判据。

`orchestrate::require_proposal_producing` 会在入口拒绝整轮。**这是正确的设计**，本需求不改它。

### 离线对照的结论（本需求的依据）

| 项 | 结果 |
| --- | --- |
| 问题关系（低分/被拒） | 28 条 |
| AI 给出可执行修正（retarget + drop） | **11 条** |
| 被采样证实 | 4 条（其余因源列全空无法验证） |
| **被采样推翻** | **0 条** |
| AI 自评置信度 vs 实测 | 自评 0.85–0.95，实测 4/4 命中 |

最有价值的一类：`llm_model` 同时有 UUID 主键与业务键 `model_id`，规则只能指 `id` ⇒ 6 条关系全错。**这是纯语义判断，规则永远修不好。**

### 目标

让 AI 在**窄范围**内参与，且**可复算、可审计、可关闭**：

```
规则抽候选 → 采样证据 → [AI 语义判断（可选、带缓存）] → 评分卡 → 分档
                              ↑
                    指纹 = sha256(输入 + prompt + model + agent_version)
```

**AI 只贡献 `semantic_fit`（权重 0.15），不改变结构，不推翻 veto。**

## 范围

### 做

1. **指纹缓存**：`ai_cache(fingerprint, output_json, model, prompt_sha, created_at)`；同指纹必须命中，不重复调用
2. **AI 语义通道**：对「候选关系」判定「语义是否说得通」，产出 `semantic_fit`（0–1）+ `rationale`（≤60 字）+ `cites`（引用的表/列坐标）
3. **接入评分卡**：`semantic_fit` 权重 0.15，按可用信号重新归一化
4. **预算闸**：`--budget-tokens` **默认强制非零**（AI 开启时）
5. **可关闭**：`--no-llm`（默认关）；无 key 时**明确报错**，不静默降级
6. **溯源**：提案条目带 `ai: {model, prompt_sha, tokens, cache_hit}`

### 不做

- ⛔ 不让 AI 产结构（表→实体、列→属性、键）
- ⛔ 不让 AI 改写 veto（语义分再高，0 命中仍是 ≤0.20）
- ⛔ 不做动作层（ActionType，独立需求）
- ⛔ 不把 AI 打分发进客户视图

## 关键设计判断（已定，Dev 不必再猜）

| # | 问题 | 裁定 |
| --- | --- | --- |
| R1 | 缓存键 | `sha256(规范化输入 + prompt_sha256 + model_id + agent_version)`；**缺 prompt 项等于静默错** |
| R2 | 缓存未命中 | 调用模型并写入；**命中则绝不调用** |
| R3 | `--refresh` | 显式忽略缓存并覆盖（用于迭代 prompt），必须打印「强制刷新 N 条」 |
| R4 | 无 key | **报错退出**（exit≠0），⛔ 不许「静默跳过 AI 继续跑」——否则产物会看起来正常但实际没跑 |
| R5 | 预算 | AI 开启时 `--budget-tokens` 必填且 >0；超预算**停止**并报告已用/上限 |
| R6 | AI 判断失败 | 该条 `semantic_fit` 缺失 → 按「无此信号」归一化，**不得**记为 0（0 = 明确否定，缺失 = 没判断） |
| R7 | 语义分上限 | `semantic_fit` 只能抬高「结构+数据」已支持的分数，**不得翻转任一 veto** |

## 风险

| # | 风险 | 缓解 |
| --- | --- | --- |
| 1 | 供应商侧模型漂移 | 缓存 + `model` 记入指纹 |
| 2 | 提示词改了却复用旧结果 | prompt_sha 进指纹（R1） |
| 3 | AI 编造引用 | `cites` 必须是真实存在的 `表.列`，导入时校验 |
| 4 | 成本失控 | 预算闸默认强制 + 缓存命中率高 |
| 5 | 语义分被当成事实 | 权重仅 0.15；veto 不可翻转 |

## 交付物

1. `ai_cache` 表 + 迁移
2. AI 通道（复用 `agent/llm` transport）+ prompt 模板与 `prompt_sha256`
3. `semantic_fit` 接入评分卡
4. `--no-llm` / `--refresh` / `--budget-tokens` 三个开关
5. `scripted transport` 的单元/集成测试（**无 key 也能全绿**）
6. 离线对照的复现脚本（AI 关 / AI 开 的分数对比）
7. 已知限制
