# 需求：REQ-128 · `ontok-propose --names` 改为必填

## 基本信息

| 项 | 值 |
| --- | --- |
| 需求编号 | REQ-128 |
| 优先级 | **P0**（部署陷阱：静默用占位表） |
| 状态 | 进行中 |
| 基线 | `develop` `1a7e1b4` |
| 触发 | 用户问「这几个样例文件会不会影响 agent 判断」→ 查出来 `--names` 的默认值是一个**脱敏占位表** |

## 问题

```rust
// src/bin/ontok-propose.rs:58
let mut names_path = String::from("src/extract/table_names.json");
```

`table_names.json` 是**脱敏样例**（91 条全是 `t001 → 对象 001`）。它作为默认值有三种后果：

| 场景 | 实际后果 |
| --- | --- |
| 容器里不传 `--names` | 去 `/data/src/extract/table_names.json` 找文件 → **报"文件不存在"**（镜像里没有 src/） |
| 仓库根目录跑、不传 | 读到**占位表** → 实体名全是「对象 001」→ **白跑一轮抽取** |
| 忘了传 | 同上，而且**不报错** |

**这不是"被带偏"，是"静默白跑"** —— 与「宁可不产出，不产出错的」口径冲突。

## 要做

1. **去掉默认值**：`--names` 必填；不传 ⇒ **启动即失败**，错误信息可行动：
   > 必须显式提供翻译表（`--names`）。默认的 `src/extract/table_names.json` 是**脱敏占位样例**（t001→对象 001），不能用于真实抽取。
   > 用 `ontok-translate-names` 或 `ontok name suggest --as-names` 生成后再传。
2. **不让占位表冒充真实表**：即使显式传了占位表，也要**警告**（检测 key 形如 `t\d{3}` 且 value 形如 `对象 \d{3}` 时提示）。⚠️ 警告而非拒绝——本地测试仍可能需要它。
3. 更新所有依赖默认值的测试/脚本，改为显式传 `--names`（用脱敏 fixture）
4. 文档同步：`--help`、README、runbook 里的示例命令

## 不做

- ⛔ 不改 `table_names.json` 的内容（它作为脱敏样例仍有价值）
- ⛔ 不改抽取算法

## 关键裁定

| # | 裁定 |
| --- | --- |
| R1 | **必填**，不传立即失败（退出码非 0） |
| R2 | 传了占位表 → **警告但不拒绝**（本地测试需要） |
| R3 | 错误信息必须说明「为什么不能默认」+「怎么生成真实表」 |
| R4 | 不破坏既有测试语义：只改「怎么拿到路径」，不改判据 |

## 交付物

1. 必填 + 可行动错误信息
2. 占位表警告（含检测规则）
3. 受影响的测试/脚本修好
4. 文档同步
5. 已知限制
