## 一 · 一句话

> console 不是"管理控制台"，是**一个本地评审台**：
> **草稿进来 → 人逐条签 → 定版 → 导出 `.ontokbundle` →（人工）传 Studio**。
> 没有口令、没有"项目"、没有上传、没有入库、没有激活。

## 二 · 定位对照

| 维度 | 现在（REQ-161 之后） | REQ-162 |
| --- | --- | --- |
| 身份 | 8→6 个视图的管理台 | **一屏：评审 + 导出** |
| 口令 | `--tokens` + 管理口令框 | **无口令**（只绑 127.0.0.1） |
| 项目 | 建项目 / 选项目 / 多版本压在库里 | **一个工作目录 = 一个项目**；不建、不选 |
| 存储 | 本地 Postgres（proposals / ontology_versions） | **工作目录里的文件**（无库） |
| 构建包 | 上传 / 配 DSN / 解析入库 / 激活 / key | **一个按钮：导出包**（导出的是**定版**） |
| 核心 | 项目/评审/导出/声明/审计/构建包 | **评审** + 导出 |

## 三 · 状态模型（这是本单的骨架）

```
           agent 产出               人逐条裁决                点「定版」              点「导出包」
  ┌──────────────────┐    ┌──────────────────────┐   ┌──────────────────┐   ┌───────────────────────┐
  │ out/proposal.json│ →  │ .ontok/decisions.json│ → │ .ontok/versions/ │ → │ .ontok/bundles/*.ontokbundle │
  │      （草稿）      │    │   （人签记录）         │   │   vN/snapshot.json│   │     （只含定版）        │
  └──────────────────┘    └──────────────────────┘   └──────────────────┘   └───────────────────────┘
```

| 概念 | 落地 | 说明 |
| --- | --- | --- |
| **草稿** | `<workdir>/out/proposal.json` | agent 的产物，**只读**（页面不改它） |
| **裁决** | `<workdir>/.ontok/decisions.json` | 逐条 `{key, biz, model, reason}`；人签 |
| **定版** | `<workdir>/.ontok/versions/v<N>/snapshot.json` + `meta.json` | 由「草稿 + 裁决」算出；**冻结、不可改** |
| **构建包** | `<workdir>/.ontok/bundles/<dir>-v<N>.ontokbundle` | 从**定版**打包（复用 `bundle::pack`） |

⛔ 定版之后草稿再变，**旧定版不跟着变**（这是"定版"的意义）；要改就再定一版 v(N+1)。

┌──────────────────────────────────────────────────────────────┐

│                                │   171,735 B · sha256 c6f9…   │

**页面只做四件事**：读草稿 · 记裁决 · 定版 · 导出。⛔ 不做：登录、项目、上传、DSN、入库、激活、key、审计、声明编辑。

## 五 · 本地 API（全部本地文件，无库、无口令）

| # | 端点 | 作用 |
| --- | --- | --- |
| 1 | `GET /api/state` | 目录名 · 草稿是否存在 · 条数与进度 · 最近定版号 · 是否已有 bundle |
| 2 | `GET /api/draft` | 草稿全文 + 每条当前裁决（合并 `decisions.json`） |
| 3 | `POST /api/decide` | 记一条裁决（`biz` / `model` 两轨 + `reason`）；写 `decisions.json` |
| 4 | `POST /api/finalize` | 把「草稿 + 裁决」算成定版 v(N+1)（`snapshot.json` + `meta.json`）；**要求全部签完** |
| 5 | `GET /api/versions` | 定版列表（号 / 时间 / 条数 / sha256） |
| 6 | `POST /api/bundle` | 从指定定版打包到 `.ontok/bundles/`，回 `{file, bytes, sha256}`；页面提供下载 |

**删掉**：`/api/projects*`、`/api/import`、`/api/apply`、`/api/freeze`、`/api/export/ttl`、`/api/r2rml`、`/api/audit`、`/api/review`、`/api/decide`（旧的库版）。
⚠️ 冻结/导出的旧语义由「定版 + 导出包」替代，⛔ 不要两套并存。

## 六 · 验收

- **AC-001** 无口令：`console serve` 不再需要 `--tokens`；`/` 与 `/api/*` 都不带凭据；**只绑 127.0.0.1**（非回环仍拒）
- **AC-002** 无项目：启动只要 `--dir <工作目录>`；页面不出现"项目/版本"选择器
- **AC-003** 草稿只读：页面改不了 `out/proposal.json`（字节不变）
- **AC-004** 裁决持久：刷新/重开页面后已签条目仍在（读 `decisions.json`）
- **AC-005** 定版：签完才能点；定版后 `snapshot.json` 冻结；草稿再变不影响旧定版
- **AC-006** 导出的是定版：包里快照 == `.ontok/versions/vN/snapshot.json`（逐字节）；`bundle verify` exit 0
- **AC-007** 零库依赖：`ONTOK_DATABASE_URL` **不设**也能跑通全流程（这是最硬的一条）
- **AC-008** 页面体积 ≤300KB、零外部资源、无 localStorage（裁决在服务端文件里）

## 七 · 不做

| ⛔ | 理由 |
| --- | --- |
| 上传/入库/激活/key/DSN | 那些是 Studio 的事（ADR-013）；本机只出包 |
| 与 Postgres 的任何交互 | 用户口径「纯本地」；库是服务面的事 |
| 多项目/多版本并存 | 一个目录一个项目；定版号自增即可 |
| 保留旧页面做兼容 | 两套并存会让人不知道该点哪个 —— 直接替换 |
