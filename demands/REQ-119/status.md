## 上游决策（用户与老板）

```
本体 TTL ──▶ 数字员工（Agent 读 schema、写 SPARQL）
                  │
                  ▼
         服务端 SPARQL 引擎 ──R2RML 映射──▶ 关系库
                  │
                  ▼
         结果表 ──▶ Agent 解释 ──▶ 客户
```

这是标准 **OBDA**（Ontology-Based Data Access）架构。

## 实测差距（为什么需要本需求）

| 要素 | 现状 | 后果 |
| --- | --- | --- |
| `owl:inverseOf` | **0 条** | Agent 从「客户」走不到「它的扣费」 |
| `rdfs:range` | **895 条全是 `rdfs:Literal`** | Agent 不知道能不能 `SUM(金额)` |
| IRI 模板 | 无 | R2RML 生成的实例 IRI 与 TTL 对不上 |
| 租户标注 | 无 | **客户 A 可能查到客户 B 的数据** |

## 替身实验的持久价值

**「代码全绿 ≠ Agent 能用」**：5 题语法全对，只有 1 题能交付客户；差的那 3 题**全卡在信息缺失**（主键、枚举、FK 边），不是语法。
这条实验方法（只给 TTL、只写 SQL/SPARQL、不执行、人工判）应当成为后续每个消费端需求的**标准验收**。
