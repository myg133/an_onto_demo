# 需求：REQ-119 · 本体可查询化（为 OBDA / 数字员工铺路）

## 基本信息

| 项 | 值 |
| --- | --- |
| 需求编号 | REQ-119 |
| 优先级 | **P0**（数字员工链路的第一块地基） |
| 状态 | 进行中 |
| 基线 | `develop` `2b55624` |
| 上游决策 | 用户与老板确定的消费架构：**TTL 给数字员工 → Agent 用 SPARQL → 服务端 R2RML 查询 → Agent 解释** |

## 需求描述

### 目标架构（OBDA）

```
本体 TTL ──给──▶ 数字员工（Agent 读 schema、写 SPARQL）
                      │
                      ▼
              服务端 SPARQL 引擎 ──按 R2RML 映射──▶ 关系库
                      │
                      ▼
              结果表 ──▶ Agent 解释 ──▶ 客户
```

### 现状差距（实测）

| 要素 | 现状 | 问题 |
| --- | --- | --- |
| TTL | 83 类 / 866 数据类型属性 / 52 对象属性 | 见下四条 |
| R2RML | **完全没有** | REQ-120 |
| SPARQL | **完全没有** | REQ-121 |
| 反向属性 | `owl:inverseOf` **0 条** | Agent 从「客户」走不到「它的扣费」 |
| 数据类型 range | `rdfs:range rdfs:Literal` **895 条全是它** | Agent 不知道能不能 `SUM` |
| IRI 模板 | 无约定 | R2RML 生成的实例 IRI 与 TTL 对不上 |
| 租户标注 | 无 | **客户 A 可能查到客户 B 的数据** |

### 本需求做什么

把导出的 TTL 从「给人看的本体」升级成「**给 Agent 查的本体**」：

1. **反向属性**：每条对象属性生成反向属性 + `owl:inverseOf` 双向声明
2. **xsd range**：按列类型映射（`xsd:decimal` / `xsd:integer` / `xsd:dateTime` / `xsd:string` / `xsd:boolean`）
3. **IRI 模板**：每个类声明实例 IRI 模板（R2RML 必须产出**同一个** IRI）
4. **租户标注**：按声明文件标注租户键列；**未标注时必须在 TTL 里显式标记**

## 关键裁定

| # | 问题 | 裁定 |
| --- | --- | --- |
| R1 | 反向属性的命名 | `<对象>__<主语>`（与正向的 `<主>__<宾>` 对称，可读）。例：`:扣费明细__客户` 的反向是 `:客户__扣费明细` |
| R2 | 反向属性是否也带 `rdfs:domain/range` | **带，且对调**（反向的 domain = 正向的 range） |
| R3 | xsd 映射失败怎么办 | 映射到 `xsd:string`，但**必须在 stats 里计数并列出**（⛔ 不许静默） |
| R4 | 租户标注放哪 | **只在建模视图 TTL**；客户视图 TTL 不含（租户键是建模/安全信息） |
| R5 | 没有租户声明时 | 导出**成功**，但文件头 + `ontok:tenantUnannotated true` 双重标记，stderr 警告「这份本体不能直接给数字员工用」 |
| R6 | 确定性 | 同版本两次导出逐字节相同（反向属性排序稳定） |

## 范围

### 做

1. `owl:inverseOf` + 反向属性（含 domain/range 对调）
2. xsd range 映射（含失败计数）
3. `ontok:instanceIri` 模板（每个类）+ 文档化的 IRI 约定
4. 租户声明文件（`tenancy.json`）：`{columns, tables?, reviewed_by}` → 标注 `ontok:tenantKey`
5. 未标注时的显式标记与警告
6. **验收验证**：5 个真实业务问题，让 Agent 只读 TTL 写 SPARQL（不执行），人工判对错

### 不做

- ⛔ 不实现 R2RML（REQ-120）
- ⛔ 不实现 SPARQL 引擎（REQ-121）
- ⛔ 不改抽取/评分/分组
- ⛔ 不引新依赖

## 风险

| # | 风险 | 缓解 |
| --- | --- | --- |
| 1 | 反向属性让 TTL 体积翻倍 | 可接受（当前 215 KB → 约 260 KB）；R2RML 更需要它 |
| 2 | xsd 映射把 `numeric` 都当 decimal 导致精度问题 | 记录原列类型作为注释；聚合用 decimal 足够 |
| 3 | 租户列判断错 = 安全漏洞 | 声明文件**必须人签**（`reviewed_by`）；未签则标 `tenantUnannotated` |
| 4 | Agent 仍可能写错 SPARQL | 本需求只验证「**能不能写对**」，执行与限制在 REQ-121 |

## 交付物

2. 反向属性、xsd range、IRI 模板、租户标注的**计数与样例**
3. 未标注租户时的警告实测
4. 确定性与体积变化
5. **5 个业务问题的 SPARQL 试验**（不执行，只看写得对不对）
