## 一 · H1 · JSON 出口先 emit 后判定

### 现状（源码确定，BA 已逐行核实 `src/cli.rs:1301-1307`）

```rust
let json = serde_json::to_string_pretty(&filtered.view)?;
let leaked = scan_modeling_terms(&json);
crate::cli::emit_domain_line(&json);          // ← 先写出去
if !leaked.is_empty() {
    println!("\n⚠ 客户视图泄露了建模术语：{leaked:?}");   // ← 且清单打进 stdout
    std::process::exit(crate::cli::EXIT_LEAKED_MODELING_TERMS);
}
```

⇒ `ontok ontology show --project X --version N > out.json` 在泄漏时**仍然写出完整数据**，
退出码 2 只是**事后信号**。**「客户视图不得含建模术语」这条承诺，在 JSON 出口上可绕过。**

### AC-001 · 判定必须在写出**之前**

- 顺序必须是：**判定 → 不通过则拒发 → 通过才写出**
- ⛔ **不许保留任何「先写后判」的路径**

## 二 · H1 附带 · 泄漏清单混进了 stdout

`println!("⚠ 客户视图泄露了建模术语：{leaked:?}")` 把清单打进 **stdout**，
与 JSON **混在同一条流里** ⇒ `… | jq` 直接解析失败。

### AC-002 · 诊断信息一律走 stderr

- 泄漏清单、剔除报告、所有诊断**必须走 stderr**
- stdout 上**只允许出现该出口承诺的那一种格式**

⚠️ 同类问题：`cli.rs:1296-1299` 的 `eprintln!("{report}")` 已经在 stderr，**保持**。

## 三 · H2 · 首页零闸，项目名原样进 JS

### 现状（BA 已核实 `src/server/http.rs:262-264` + `src/server/page.rs:117/267`）

```rust
async fn index(State(state): State<AppState>) -> Html<String> {
    Html(crate::server::page::index_html(&state.project, state.version))
}
```
```rust
var who = { project: "%%PROJECT%%", version: %%VERSION%% };
…
.replace("%%PROJECT%%", project)     // ← 原样注入 JS 字面量，不过任何闸
```

⇒ ① 项目名含建模术语时**不拦**；② 项目名含引号/反斜杠**能破坏脚本结构**（项目名是建项目时用户输入的）。

⚠️ **口径不一致**：同一份项目名在 MCP 侧走 `tools.rs:742` **做了** scan + 替换。

### AC-003 · 首页必须与其它出口口径一致

- 项目名进页面前**必须过与 MCP 侧同一道判据**
- ⛔ **不许新写一份**（纪律 H：复用 `mcp::tools::guard` 本身）
- 项目名**必须安全转义**进 JS 字面量（含 `"` `\` `<` `/` 等）

### AC-004 · 注入面有测试钉住

- 构造项目名含 `"` / `\` / `</script>` 等，**页面必须仍是合法 HTML 且 JS 结构不被破坏**
- ⚠️ 有测试，且**变异验证会红**（三元组见纪律 G）
