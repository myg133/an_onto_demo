# 需求：REQ-115 · 概念分组与图上的归并

## 基本信息

| 项 | 值 |
| --- | --- |
| 需求编号 | REQ-115 |
| 优先级 | **P1** |
| 状态 | 进行中 |
| 基线 | `develop` `71ae770` |
| 触发 | 用户实测：「归并没效果？」「要不要做聚类？」 |

## 需求描述

### 先说清「为什么现在没效果」

| 层 | 现状 | 证据 |
| --- | --- | --- |
| **数据** | `anspire_excl` 里概念组 = **0** | `select count(*) from concept_groups` → 0 |
| **API** | 图接口的 `parent` **写死为 `None`** | `src/server/http.rs:755` `parent: None,` |
| **页面** | 无分组渲染 | 页面里 `group`/`cluster`/`concept` 0 命中 |

⇒ **不是归并失效，是归并这件事没接进图里。**

REQ-010 早就实现了概念组（`concept import` → 双轨审核 → 落库），但从没接到图上；这次的 84 张表也从未做过分组。

### 目标

```
AI/算法产出分组声明（concept declaration）
   → concept import（双轨审核，人签）
   → 落库 concept_groups
   → /api/graph 返回组成员
   → 页面：按组聚拢 / 组圈 / 折叠 / 组面板
```

## 两层设计（**权威 vs 建议**必须分开）

| 层 | 是什么 | 权威性 | 落点 |
| --- | --- | --- | --- |
| **权威层** | 概念组（`concept_groups`）：人签过的业务域划分 | ✅ 可评审、可推翻、进快照与导出 | 已有（REQ-010），本需求**接到图上** |
| **建议层** | `concept suggest`：从关系拓扑算候选分组，**只产出声明文件**，不入库 | ❌ 不权威，仅作提案 | 本需求新增 |

⛔ **绝不允许**「页面自己算一套分组」当作归并显示——那就是「看着有分组，其实没人签过字」。

## 范围

### 做

1. **`/api/graph` 返回分组**：`groups: [{key, display_name, members[], reason?}]`；节点带 `group` 字段（无组则为 `null`）
2. **页面渲染**：
   - 组圈（背景圆/凸包）+ 组名
   - **折叠/展开**：折叠后显示聚合节点（组名 + 成员数），展开还原
   - 组面板：列出成员，点击定位
   - 组内聚拢：组心作为额外引力（可在同一套力导向里加）
3. **`ontok concept suggest --project --version [--out]`**：确定性社区检测（如标签传播/Louvain 简化版），产出**可直接 `concept import` 的声明 JSON**，⛔ 不写库
4. **无组时如实显示**：页面显示「未分组」并提供入口提示，⛔ 不虚构分组
5. **声明文件可往返**：`suggest` 产出 → `concept import` → 审核 → apply → 图上出现该组（AC-005）

### 不做

- ⛔ 不让页面自己算分组（见上）
- ⛔ 不做「AI 命名」（下一轮；本轮组名来自成员的主导表名，或声明文件里显式给出）
- ⛔ 不新增外部依赖（算法手写）
- ⛔ 不改 `concept import` 的审核语义

## 关键裁定

| # | 问题 | 裁定 |
| --- | --- | --- |
| R1 | 权威 vs 建议 | 图上**只显示权威分组**；建议只存在于声明文件里，进审核后才可能变成权威 |
| R2 | 折叠的语义 | 折叠是**纯视觉**，不改数据、不影响导出与客户视图 |
| R3 | 组的名字 | 声明文件里给（AI/人可改）；`suggest` 用成员中最高度数表的显示名兜底 |
| R4 | 确定性 | `suggest` 同版本两次 ⇒ 声明文件**逐字节相同**（算法不许有随机种子漂移，或固定种子） |
| R5 | 规模 | 84 节点 / 82 边要在浏览器里流畅；折叠后节点数可降到个位数 |
| R6 | 无组的诚实性 | 页面必须能区分「没有分组」和「分组为空」，⛔ 不许用一个默认组把一切塞进去 |

## 风险

| # | 风险 | 缓解 |
| --- | --- | --- |
| 1 | 建议被当成结论 | 声明文件里写 `source: "algorithm-suggest"` + `reviewed_by: null`；审核界面显示来源 |
| 2 | 算法分组毫无业务意义 | 允许人改；`suggest` 只是「省打字」，不是「替人决定」 |
| 3 | 图变复杂反而更难读 | 折叠默认开启（按组折叠成 N 个节点），点开才展开 |
| 4 | 与 REQ-114 的拖拽/碰撞冲突 | 组心引力与碰撞要一起收敛；探针要能验证折叠态 |

## 交付物

1. `/api/graph` 的 `groups` + 节点 `group`
2. 页面：组圈、折叠/展开、组面板、组内引力
3. `concept suggest`（确定性、不写库）
4. 真实库实测：84 个对象分成 N 组（AI 或算法提案），审核后图上可见
5. 往返验证：`suggest` → `import` → `review` → `apply` → 图
6. 已知限制
