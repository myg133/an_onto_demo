## 四 · 阶段 1 裁定（2026-10-25）

### R-A · 签名对拍：**接受**，且中间量全部对齐

官方文档《签名方法 v3》唯一带密钥示例（`cvm` / `1551113065`）：`Authorization` 与
`Signature=10b1a37a…6ab6c4f` **逐字节相同**，且 `Date` / `HashedRequestPayload` / `CanonicalRequest` /
`StringToSign` / 三把派生密钥**逐项相等**。

**为什么这条判据够硬**：它证明的不是"输出像"，是**每个中间环节都对**——签名错时真调用只回一个看不懂的 401。

**⚠️ 第二组向量的来源已如实标注**：文档只公布一组（SecretKey 打码），第二组用**文档同一份 Python 实现**复算，
测试注释写明"⛔ 不要说成文档公布的期望值"。**这个处理正确。**

### R-B · 零新增依赖：**接受**，但记两条代价

`sha2`/`hmac` 在 lock 里（传递依赖），提成直接依赖会改 `Cargo.toml`/`Cargo.lock` ⇒ 手写 SHA-256/HMAC（~120 行）。

1. 手写密码学原语**必须**靠标准向量证明（FIPS 180-2、RFC 4231 §4.2/4.3/4.6 已做）
2. 将来换算法时，这段是自维护代码，**不如现成库**——那时应重新评估"零依赖"是否值得

### R-C · `DRY_RUN_REQUIRED` 文案变更：**接受**

原话「本程序里**没有**那条路径」在阶段 1 之后**变成假话** ⇒ 必须改（**说假话比改文案更糟**）。码与退出码未变。

### R-D · ⚠️ **流程违规：证据目录放在 `%TEMP%`**

Dev 把证据放在用户临时目录（`C:\Users\…\AppData\Local\Temp\ontok-req144-stage1\`）。

**规程**：子 agent 的临时产物**必须放 worktree 的 `.local/`**（已忽略），原因：
① 重启会被清 ② 同机多 agent 的临时目录会混 ③ 审查时按 worktree 找证据。

**裁定**：**不阻断合并**（证据真实且路径已声明），但必须把证据复制进
`feature-REQ-144b/.local/req144-stage1/` 并在交付写一行"原临时路径作废"。

⇒ 记入 `dispatch/rules.md` 复述清单（同类第二次：上次是 QA 在 `D:\` 根建 9.5 GB 目录）。

### R-E · 一条**必须真调用先验**的已知限制

> `request.from_filter` 的 `zone → Zone` 是**作者声明**；腾讯云 `DescribeInstances` 真实接口
> **可能要求 `Filters[].Name=zone`** —— 必须用真响应校准。

**这是真风险**：签名对、传输对，但**参数位置错**，真调用照样失败或返回错数据。

⇒ 下一轮（真调用）**第一件事**验这条；验证之前，⛔ 不许说"映射已可跑真实 API"。

## 五 · QA 复验裁定（阶段 1，2026-10-25）

### R-G · 结论：**PASS，可合并**；但三件小事要在合并前修

QA 做的是**真正独立的复验**（这比它自己的单测有价值得多）：

| 项 | QA 怎么验的 | 结果 |
| --- | --- | --- |
| 签名 | 用 **Python hashlib/hmac** 按文档四步自己算 | `Signature=10b1a37a…` **逐字节相同** |
| 手写 SHA-256/HMAC | `#[path]` 直接编译原文 `tc3.rs` 对拍 Python，**81 个字段** | **0 处不同**（含 55/56/64/119/120 边界、key=0/64/65/131） |
| 是否联网 | 裸 TCP 监听器，四场景 | **accept 0 次 / 0 字节** |
| 五类错误 | 自建假端点，9 个请求的 `Authorization` 全部 Python 独立复算 | **9/9 全中** |
| 零回归 | 自建基线二进制（`git archive` + 独立 target） | **7/8 逐字节相同**，唯一差异是 R-C 已裁的文案 |

### R-H · 三件必修（都小，但不修就是"留一句假话"）

| # | 问题 | 为什么必修 |
