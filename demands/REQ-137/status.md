# 状态：REQ-137 · 本体模式不强制 tenant

## 当前状态

**进行中**（2026-10-24 开单 · P1）

## 怎么发现的

部署 Ops360 到集群时，Pod 起不来：

```
✗ token 表 "/etc/ontok/secrets/query-tokens.json" 不合法：missing field `tenant`
```

**本体模式（`--ontology-only`）没有业务库、没有租户**，但 token 结构把 `tenant` 当必填。

临时填了 `00000000-0000-0000-0000-000000000000` 让它跑起来——
但**审计日志里会出现一个"看起来真实"的租户 id**。

> 这正是这套系统一直在防的：**假数据冒充事实**。

## 裁定

| # | 裁定 |
| --- | --- |
| R1 | 普通模式：`tenant` **仍必填**（零行为变化） |
| R2 | 本体模式：`tenant` **必须缺省**；填了 ⇒ **拒绝启动** |
| R3 | 本体模式审计行：`tenant=-`（明确"没有租户"） |
| R4 | 报错必须说明「为什么不能填假租户」 |

**为什么"填了就拒绝"而不是"忽略"**：
忽略会留下更坏的东西——一个**声明了数据范围、但范围不存在**的 token。
