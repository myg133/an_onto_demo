## ② 中文值域的判据

### 判据代码

`src/extract/propose.rs` · `is_han_value_domain()`：

```rust
fn is_han_value_domain(s: &str) -> bool {
    // ⚠️ 不能先按分隔符切原子 —— 空格在值域里身兼两职：
    //   `0: 未分类` 里它是「编码和值之间」的，`0=禁用 1=启用` 里它是「两项之间」的。
    let chars: Vec<char> = s.chars().collect();
    let mut i = 0;
    let mut pairs = 0usize;
    while i < chars.len() {
        while i < chars.len() && (chars[i].is_whitespace() || VALUE_SEP_CJK.contains(&chars[i])) { i += 1; }
        if i >= chars.len() { break; }
        // 读「编码」：到配对符为止。编码里不许有空白，也不许有汉字
        let code_start = i;
        while i < chars.len() && !PAIR_SEPS.contains(&chars[i]) && !chars[i].is_whitespace() { i += 1; }
        let code: String = chars[code_start..i].iter().collect();
        if code.is_empty() || code.chars().any(crate::domain::view::is_han) { return false; }
        if i >= chars.len() || !PAIR_SEPS.contains(&chars[i]) { return false; }
        i += 1;
        while i < chars.len() && chars[i].is_whitespace() { i += 1; }   // `0: 未分类` 的空格
        let val_start = i;
        while i < chars.len() && !chars[i].is_whitespace() && !VALUE_SEP_CJK.contains(&chars[i]) { i += 1; }
        if i == val_start { return false; }
        pairs += 1;
    }
    pairs >= 2
}
```

挂在 `classify_comment` 的**汉字门槛之前**（顺序是关键）：

```rust
pub fn classify_comment(sanitized: &str) -> CommentQuality {
    // ⚠️ 必须排在汉字门槛之前：`0: 未分类` 里的汉字是**值**不是**名字**
    if is_han_value_domain(sanitized) { return CommentQuality::EnumDomain; }
    if sanitized.chars().any(crate::domain::view::is_han) { return CommentQuality::HumanReadable; }
    if is_enum_domain(sanitized) { return CommentQuality::EnumDomain; }
    CommentQuality::LowQuality
}
```

**一句话判据**：*每一个原子都是「纯编码 `[:：=]` 值」的配对，且整条没有一个多余片段。*

**核心区分**：「有汉字」≠「是人话」。汉字可以出现在**值**里（`未分类`），
也可以出现在**独立说明**里（`状态`）。区别在于 ——
**值域里每个汉字都被一个编码「领走」了；人话里有一段汉字不属于任何配对。**

### 4 正例 / 4 反例

| 注释 | 判定 | 为什么 |
| --- | --- | --- |
| `0: 未分类, 1: 个人用户, 2: 企业用户` | **值域** | 3 个原子全是配对，无独立说明 |
| `0: 未认证, 1: 已认证` | **值域** | 同上 |
| `0=禁用 1=启用` | **值域** | `=` 也是配对符 |
| `0: llm, 1: emb` | **值域** | 与 REQ-007 同一形态，走同一条路 |

| `用户类型 个人:person 公司:Corp` | 人话 | `用户类型` 独立；且 `个人` 在配对符**左边**（是键名不是编码） |
| `商品状态:active-启用,inactive-停用` | 人话 | `商品状态` 独立 |
| `是否启用：true=启用，false=禁用` | 人话 | `是否启用` 独立 |

### 遵守的两条硬约束

- **不是枚举表** —— 判据是形态/结构规则（配对是否穷尽），词表一条没加。
- **没退回按占比** —— 与汉字占比完全无关。REQ-005 那三条（占比 0.40 / 0.44 / 0.36）**全部仍然判为人话**，
  由 `test_mixed_chinese_comments_are_never_rejected`（原测试，一个断言没动）钉住。
