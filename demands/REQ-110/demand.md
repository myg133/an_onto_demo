## 需求描述

### 两个障碍，一个根因

**障碍 1 · TTL 是手工环节**

规格 §5.5 已经写好 OWL 对照表，但产品**没有导出命令**——这次是我用外部 Python 脚本把 `--model-view` 的 JSON 转成 Turtle。
⇒ 换个环境、换个人，这一步就断了；而且脚本不守门禁、不保证确定性。

**障碍 2 · 页面在浏览器里打不开**

`test_req093` 的一条判据要求「未登录连有哪些路径都探测不到」，于是 `require_token` 被挂在**全局**（`http.rs:449-458`），连 `/` 这个**静态页面壳**也拦。
⇒ 页面里那个「访问口令」输入框永远等不到人：要看到页面得先有口令，要有口令得先看到页面。

### 目标

跑完完整流程后：

```
ontok ontology export --format ttl      ← 产品自己能导出
ontok serve --project X --version N     ← 浏览器打开页面
   ├─ 看到本体关系图（已有能力，但要能打开）
   └─ 点「导出 TTL」直接下载
```

## 范围

### 做

1. **`src/domain/ttl.rs`**：纯函数序列化器（CustomerView / 建模视图 → Turtle），零依赖、确定性
2. **CLI**：`ontok ontology export --project --version [--model-view] [--out] [--base]`
3. **HTTP**：`GET /api/ontology.ttl`（**仍要 token**）→ `text/turtle` + `Content-Disposition`
4. **页面**：加「导出 TTL」按钮（用页内 token 拉取并触发下载）；图渲染保持现有实现
5. **页面可达性**：`/` 免 token（只是静态壳，**不含任何本体数据**），`/api/*` 仍全部 gated
6. **决策记录**：改写 REQ-093 的「未登录探测不到路径」判据 → 写一条 ADR 说明为什么改

### 不做

- ⛔ 不改实体的抽取/评分逻辑
- ⛔ 不做 RDF 导入（只导出）
- ⛔ 不引入任何新依赖（Turtle 序列化手写，不用 oxrdf/sophia）
- ⛔ 不导出动作层（OWL 无对应；**必须在文件头显式声明有损**）
- ⛔ **不做审核写操作** —— 那是**写路径**，与 `serve` 的「任何改动类请求一律 405」正面冲突
  ⇒ 已拆为 **REQ-111（本地审核界面）**，见该需求。本需求保持**只读**

## 关键设计判断（已定）

| # | 问题 | 裁定 |
| --- | --- | --- |
| R1 | 导出哪一份视图 | 默认 **客户视图**（页面看到什么就导出什么）；`--model-view` 显式选择建模视图 |
| R2 | 客户视图的 TTL 要不要过守门器 | **必须过**。TTL 是新的出口，不过闸就会变成泄漏通道（属性名/注释里的建模词会原样出去） |
| R3 | 有损项怎么处理 | 文件头用注释写清：`ActionType` 未导出（数量）、`semantic` 降级为 `rdfs:comment`、`cardinality` 只映射 Functional/InverseFunctional |
| R4 | `/` 免 token 的安全代价 | 代价是「能探测到有个服务在这」。**页面壳里不许内嵌任何本体数据**（项目名/版本/图数据都不许），数据一律走 gated API |
| R5 | 文件名 | `Content-Disposition: attachment; filename="<project>-v<n>.ttl"` |
| R6 | 确定性 | 同一版本两次导出**逐字节相同**（属性/关系按稳定顺序，不依赖 HashMap 迭代序） |

## 风险

| # | 风险 | 缓解 |
| --- | --- | --- |
| 1 | `/` 免 token 被当成「服务暴露」 | 页面壳无数据；ADR 记录取舍；`/api/*` 全部仍 401 |
| 2 | TTL 绕过守门器 | AC 明确要求「序列化后过 `scan_modeling_terms`，命中即拒绝导出」 |
| 3 | 导出与页面看到的不一致 | 两者都走同一份 `state.view` / 同一个序列化函数 |
| 4 | 新出口没人守 | 接入 REQ-107 的出口管线（`OUTLETS` 登记 + 否定式判据） |
