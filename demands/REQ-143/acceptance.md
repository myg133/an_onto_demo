### AC-003 · key 确定性（R2）

- 判据：两次 sha256；并说明 key 的派生规则（`path:line`）

### AC-004 · band 与签名（R3）

- 所有新建（`origin: "doc"`）条目：`band ∈ {low, medium}`、`reviewed_by: null`
- **变异**：把 doc 条目设成 `strong` ⇒ 必须有测试红
- 判据：逐条断言 + 变异红行

### AC-005 · 关系不许造端点（R4）

- 断言里 `subject`/`object` 有一个解析不到 ⇒ **该关系进 `doc_unmapped`**，`@graph`/提案里**不出现**这条边
- 判据：构造一条"一端不存在"的关系，验证

### AC-006 · 端到端（**最重要**）

```
doc ingest → doc merge --allow-doc-only → propose import → review decide --accept-all

```

- 产出 TTL 里**类数 = 概念数**、关系数 = 可解析的关系数
- 与"用脚本转换"的老路径相比：**TTL 内容等价**（类/关系/属性计数一致）
- 判据：贴 TTL 头部计数 + `catalog` 的 counts

### AC-007 · 冲突与排除规则不变

- `alignable: false` 仍排除并计数
- 冲突仍双保留 + `applicable: false`（apply 拒绝）
- 判据：各一条

## 三 · 裁定（Dev 提的两处）

### R-1 · AC-006 的计数口径：**用加总式，不是"类数 = 概念数"**

我 AC 里写「类数 = 概念数、关系数 = 可解析的关系数」——**这个说法是错的**，真实样本一跑就露：

| 我的朴素数法 | 实际 | 为什么不一样 |
| --- | --- | --- |
| 概念断言 506 | 去重后 **288 个名字** | 同一概念被多条断言重复抽出 |
| 288 个概念 | 新建 **281** | 7 个命中了老提案（走 `both`） |
| TTL 类 = 288 | **301** | 老提案自带 20 个实体（其中部分没有概念断言） |
| 关系 222 条 | 新建 **48** | 只有 72 条两端可解析，再按 (from,to,predicate) 去重 |

**裁定：AC-006 的判据改成加总式**

```
TTL 类数     = 老提案实体数 + 新建 doc 实体数
TTL 关系数   = 老提案关系数 + 新建 doc 关系数
并且：每个 origin=doc 的实体，都能在断言里找到一个同名概念（可溯）
```

**理由**：断言是"片段级"的，概念是"去重后"的，类是"再加老实体"的——**三个数本来就不该相等**。
拿朴素数法去核，只会得到"不符"，然后没人知道是数法错了还是实现错了。

### R-2 · 「名字优先于别名」只作用于 doc-only 路径：**接受**

我在 demand 写「该开关下其余规则一字不改」，Dev 在 doc-only 路径里改了**解析优先级**（名字 > 别名）。

**裁定：接受。** 理由：

| 项 | 判断 |
| --- | --- |
| 是否越界 | 🟡 是"改了一条规则"，但**只在开关打开时**生效 |
| 不改会怎样 | 真实样本里 **13 条概念被挤成 `ambiguous_name`**，留下没有证据的空类 |
| 有测试吗 | ✅ 专门用例 `doc_only_resolves_each_concept_by_its_own_name…` |
| 不开开关有影响吗 | ❌ 无（AC-001 六个文件逐字节相同） |

**追加要求**：这个差异必须写进 `--help` 或模块头（⛔ 不能让它在暗处）。

### R-3 · Dev 发现的一个真实摩擦（**要写进 FDE skill**）

> 「把概念 `description` 搬成 `rdfs:comment` 会让**客户视图发布闸**命中 `evidence` 而**整份拒绝导出**」

这说明：**客户视图的发布闸是按词扫描的**，概念描述里出现内部术语会被拦，而且是**整份拒绝**（不是跳过那一条）。

⇒ 已加入 skill 的「失败长相」：**"导出被拒 / 报发布闸" ⇒ 检查概念描述里有没有内部术语**。
