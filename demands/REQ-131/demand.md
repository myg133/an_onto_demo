# 需求：REQ-131 · 测试夹具缺失时的「响亮跳过」

## 基本信息

| 项 | 值 |
| --- | --- |
| 需求编号 | REQ-131 |
| 优先级 | **P3**（测试基础设施，不影响产品行为） |
| 状态 | 进行中 |
| 基线 | `develop` `1772507` |
| 来源 | REQ-130 QA 的 N-3 |

## 问题

`tests/test_req129_doc_merge.rs` 里的模式：

```rust
let Some(_) = fixture() else { return missing("...").unwrap() };
```

`missing()` 打印 `*** SKIP ***` 后返回 `None`，`.unwrap()` 对 `None` **panic** ⇒ 测试 FAILED。

**两个后果**：

| 现象 | 评价 |
| --- | --- |
| 夹具缺失时测试**失败**而不是跳过 | ⚠️ 在没夹具的机器上跑全量会**多出假红**，掩盖真正的红灯 |
| 但它**不会假绿** | ✅ 这点目前是对的 |

**理想的语义是第三种**：**响亮跳过**（打在输出里、能数出来），但**不失败**；同时——**CI 上必须能强制它变成失败**，否则"跳过"会变成"永远不跑"。

## 要做

1. **默认：响亮跳过**
   - 打印可 grep 的标记（如 `*** SKIP: <用例名> -- 缺 <夹具> -- 这条判据没有执行，不是通过 ***`）
   - 测试**正常返回**（不 panic、不失败）
2. **可强制：环境变量**
   - `ONTOK_REQUIRE_FIXTURES=1` 时，同样的缺失 ⇒ **失败**，错误信息说明「CI 要求夹具必须存在」
   - 这样 CI 可以设它，本地可以跳过
3. **可统计**：跳过时输出里带固定前缀，便于 CI 用 grep 数出「本次跳过了几条」

## 不做

- ⛔ 不引新依赖（不用额外测试框架）
- ⛔ 不改测试的**断言内容**（只改"缺夹具时怎么办"）
- ⛔ 不动 `#[ignore]` 语义（那是静态跳过，不能按环境切换）

## 关键裁定

| # | 裁定 |
| --- | --- |
| R1 | 缺夹具默认**跳过但不失败**，且**必须打印可 grep 的标记** |
| R2 | `ONTOK_REQUIRE_FIXTURES=1` ⇒ **失败**（CI 用） |
| R3 | 判据是「跳过的可数性」与「强制的可验证性」，不是"测试变绿了" |
| R4 | 只改测试基础设施；⛔ 不改任何产品代码 |

## 风险

| # | 风险 | 缓解 |
| --- | --- | --- |
| 1 | 跳过变成"永远不跑" | R2 的强制开关 + CI 配置（本次交付需说明 CI 该怎么设） |
| 2 | 改了跳过逻辑，把真断言也跳过了 | 判据：夹具**存在**时行为完全不变（同一条用例仍正常断言） |

## 交付物

1. 统一的跳 helpers + 两个环境下的行为
2. 跳过标记的可 grep 性（贴输出）
3. `ONTOK_REQUIRE_FIXTURES=1` 下的失败证据（贴输出）
4. 受影响用例清单（哪些会跳过）
5. 已知限制
