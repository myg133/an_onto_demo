# 验收标准：REQ-041 `test_pool()` 连接重试 + 行序自检加固

> 依据 REQ-040 复验收敛的两条 follow-up 写成。基线：`9ff76e6`（develop）。
> **其中连接重试这条优先级最高** —— 它已实际造成验收信号污染与会话丢失。

---

## 背景：为什么连接重试排第一

本会话（2026-10-08~09）实测，共享集群高负载时 `tests/common/mod.rs:66`
的建连接会失败，错误形态有两种：

```
连不上测试库: Connect(PoolTimedOut)        ← acquire_timeout=10s 内未握手
Connection reset by peer (os error 104)
```

两者都发生在**建连接阶段、任何测试逻辑之前**，单跑通常通过。

**实际造成的损失**（不是理论风险）：

| 现象 | 次数 | 后果 |
| --- | --- | --- |
| 全量测试被环境类失败污染 | 至少 **5 轮** | 每轮都要人工分类「代码红 vs 环境红」 |
| **子 agent 会话丢失** | **4 次** | 全部发生在共享集群高负载时段；其中 REQ-040 复验那次**丢在构造 M15b 的中途**，需另派接手 |
| 验收判读成本 | 每轮 | 「这条到底算不算失败」要回查原始日志 |

TCP 端口可连、但未在 `acquire_timeout=10s`（`src/db/pool.rs:71-80`）内完成握手 ——
这是共享集群被占满的特征（实测总连接常驻 32~38 / 100，另 5 个业务库常年占用）。

> ⚠️ **重试只能治症状，根因在集群侧**（见待裁定第 4 项：连接治理）。
> 但症状本身在我们自己代码里，可以自己修，且**它正在持续污染验收信号**。

---

## AC-001 · 连接失败可重试并最终判读

- 测试步骤：构造「前 N 次建连接失败、第 N+1 次成功」的情形
- 预期结果：`test_pool()` **重试后拿到连接并让测试正常跑完**，
  而不是整条测试直接 `panic!("连不上测试库")`
- 类型：功能

## AC-002 · 重试必须有界，且不掩盖真失败

- 测试步骤：构造「**一直**失败」的情形
- 预期结果：
  - **有限次**重试后**仍然失败并给出可读错误**
  - 错误信息里能看出**重试了几次**、最终失败原因是什么
  - **不无限重试**（不得让测试挂死）
- 类型：架构
- ⚠️ **理由**：无界重试会把「快速失败」变成「测试套件卡住」，
  比现在更糟。退避间隔要合理，且**总耗时必须显著小于一轮全量测试**

## AC-003 · 重试不得掩盖代码缺陷

- 测试步骤：审 diff + 变异
- 预期结果：**不得**把「迁移逻辑报错」也吞进重试 ——
  只有**建连接**阶段的失败才重试；
  连上之后的任何失败照旧暴露
- 类型：架构
- **理由**：这是重试最典型的失败方式 —— 范围写宽一点就把真 bug 当成抖动吞掉了

## AC-004 · 退避策略有判别力（变异自证）

- 测试步骤：至少做以下变异，**每条真的跑过**，给**二进制名 + 运行条数**：
  1. 重试次数改成 0（= 不重试，退回原状）⇒ 须在「前 N 次失败」情形下变红
  2. 重试范围放宽到「连上之后的失败也重试」⇒ 须被 AC-003 的判据杀死
  3. 重试次数写成极大值 / 无界 ⇒ 须被 AC-002 的判据杀死
- 类型：测试有效性
- **存活变异必须逐条论证**是「等价变异」还是「判据有洞」

## AC-005 · 全量测试不劣化

- 测试步骤：至少 1 轮完整 `cargo test --no-fail-fast`
- 预期结果：**524 passed / 0 failed / 1 ignored**（与 REQ-040 合并后基线一致）
- **耗时**：基线约 5~6 分钟（实测 5m51s）。重试不得显著推高总时长
- 类型：回归

## AC-006 · 行序自检加固（廉价加固，**期望非阻断**）

REQ-040 复验实证三条存活变异让 DB 前提**真被破坏且全绿**：
M13（`push_bind(*k)` 换成对 `*k` 的置换，recorder 仍记原值故绿）、
M17 / M19（让 `pushed` 不再来自那条 `push_values`）。

根因缝：**recorder 绑的是迭代变量 `k`，决定物理行序的是被绑定的值**。

QA 已知结论：**没有哪一行能封死这一类**，不要做无底洞。
所以本条**只做廉价加固**：

```rust
let kv = …;              // 取值一次
pushed.push(kv);         // recorder 与 bind 用同一个值
row.push_bind(kv);
```

- 预期结果：**M13 被杀死**
- **M17 / M19 允许继续存活**（堵不住，属已知不可封死类）
- 若这条做不通，**如实说做不通并撤回**，不要硬凑
- 类型：测试有效性（非阻断）

## 环境事实

- 共享集群 DB 很慢：`SELECT 1` p50 实测 **155~161 ms**（正常 <5 ms）；
  总连接常驻 **32~38 / 100**
- **先探延迟再判断测试慢不慢**；复现率随负载浮动，**不声称稳定值**
- 报告把「代码失败」与「环境类失败」**分开写**
- 本机**没有 `psql`、没有 psycopg**
- 共享本体库**禁 DELETE / TRUNCATE / 清空表**；源库只读
  （仅 `information_schema` / `pg_catalog`，零业务数据行）
- 口令只走环境变量，不入库、不进文件、不进日志、不进 commit message。
  测试库 `.env` 库名 `notol` → `ontol`
