# 验收标准：REQ-147

## 一 · AC

### AC-001 · 默认路径零变化（R1）

- 不给 `--agent` ⇒ `assertions.jsonl` / `stats.json` 与基线 `6f4987d` **逐字节相同**
- 判据：3 篇文档对拍 sha

### AC-002 · ACP 通路可用（输出 schema 一致）

- `--agent acp` ⇒ 产出合法的 `assertions.jsonl`（**与内置同 schema**）
- 同一份 JSONL 能被 `doc merge` 吃下（端到端跑通一次 merge）
- 判据：schema 对比 + merge 退出码

### AC-003 · 确定性（R2，**最容易漏**）

- 同一份输入跑**两次** ACP ⇒ `assertions.jsonl` **逐字节相同**
- 第二次 **0 次 agent 调用**（缓存命中）
- **变异**：去掉缓存 ⇒ 两次 sha 不同（必须有测试红）
- 判据：两次 sha + 调用计数

### AC-004 · 失败要响（R3）

| 构造 | 期望 |
| --- | --- |
| `--agent-acp-command` 指向不存在的程序 | 退出码非 0 + 点名 |
| agent 返回空/超时 | 退出码非 0，**不产出 assertions 文件** |
| 预算超限 | 停止 + 报"已用/上限"，**不产出半份** |

- ⛔ **不许静默回退到内置 LLM**（这条要有测试）
- 判据：三种构造各一次

### AC-005 · quote 机器校验（**本需求的核心价值**）

- 每条输出的 `quote` 必须能在原文里**逐字定位**
- 定位不到 ⇒ **该条丢弃**并计入 `discarded_no_quote`
- **变异**：故意输出一条编造的 quote ⇒ 必须被丢 + 计数 +1
- 判据：正常一次 + 变异一次

### AC-006 · 质量对照实验（**决定这个需求值不值得做**）

同一批文档（`.local/ops360-docs` 16 篇）跑两遍：

- **判据：如果 ACP 的 `belongs_to` 还是 0，本需求就失败**（不是"完成了"）
- 判据：贴两边的四组数字

## 三 · 复验裁定（Dev 交付后）

### R-1 · AC-006 的判据**是我的错**，改成"归属/包含类占比 > 5%"

我写的是「`belongs_to` 命中率必须 > 0」。Dev 查出：**这条字面判据结构性不可满足**——

`STRUCTURAL_PREDICATES`（`doc_ingest.rs:145`）里有 `belongs_to`，**谓词闸在计数之前就把它丢了**，所以它永远出现在不了"活下来"的统计里（`belongs_to_share.alive` 恒 0）。而 skill 要求中文名词化谓词，模型不会吐英文字面量。

**裁定：改口径为「归属/包含类谓词占比 > 5%」**

| 口径 | 内置 | ACP |
| --- | --- | --- |
| 严格归属类（归属/属于/所属/隶属） | 0.40% | 0.51% |
| **含「包含」类（宽口径）** | **1.19%** | **32.76%** |

**为什么接受宽口径**：它测的是"关系有没有落到**结构**上"（包含字段 / 取值包含 / 归属采集项），
而这正是我们要的——**能映射到实体-属性/实体-实体的边**。27 倍的差距不是噪声。

**但真正的价值证据是另三组数字**（这些才是本需求的理由）：

| 指标 | 内置 | ACP | 变化 |
| --- | --- | --- | --- |
| **泛动词占比**（使用/读取/写入/处理/进行/支持/融合/调用/获取） | 18.65% | **1.31%** | **-93%** |
| **关系两端都是概念**（不悬空） | 26.2% | **96.4%** | 3.7× |
| quote 校验通过率 | 100%（但它几乎整段照抄标题） | **98.7%**（**31 条编造/拼接被机器丢掉**） | — |

### R-2 · AC-003 的确定性：**接受"有条件成立"，但必须显式化**

Dev 实测：run1 有 2/95 块传输级失败 ⇒ 那 2 块不进缓存（REQ-116 纪律：失败要能重试）⇒ run2 重调、输出变。

**裁定：采纳 Dev 的 A + C**

| 项 | 内容 |
| --- | --- |
| **A** | 屏幕上**必须**报："本轮 N 块失败，重跑会重调这 N 块 ⇒ 产物可能变化"（用 `stats.failed_calls`，零语义改动） |
| **C** | 新增 `--strict-deterministic`：本轮 `failed_calls > 0` ⇒ **exit≠0 且不产出产物** |

**⛔ 不采纳 B**（让失败也进缓存）：那会把**一次瞬时故障变成永久结论**，比不确定性更糟。

**判据改写**：AC-003 的成立条件 =「**首轮所有块都有回答**」；`--strict-deterministic` 下**无条件成立**（否则不产出）。

### R-3 · 对照实验**必须分离模型变量**（这条是硬要求）

Dev 自己指出：ACP 侧是 `pi-acp` + `MiniMax-M2.7`，内置侧是 `deepseek-v4.1-flash`。

> **所以"ACP 更好"里混了"模型更强"这个变量。skill 的价值未被证明。**

**裁定：必须补一组同模型对照**（用 `session/set_config_option` 把 pi 切到 deepseek）。

若切换失败 ⇒ **如实报"未能分离"**，并在结论里降级为「ACP+MiniMax 优于内置+deepseek」，**⛔ 不许说成"我们的 skill 更优"**。

### R-4 · skill 与解析器形状不一致：**改 skill，不加第二份契约**

Dev 的处理是"在 system prompt 末尾追加 OUTPUT_PROTOCOL 做仲裁，skill 一个字不改"。

**问题**：这等于**同一条要求写了两份**（skill 里说 JSONL，运行时说 JSON 对象）——违反我们刚立的「一个行为只在一个文档定义」。

**裁定：我来改 skill**——§一 改成"**语义契约**（抽什么、证据怎么给），**输出形状由调用方的运行时指令指定**"。这样 skill 保持通用，且不再与任何通道冲突。

## 四 · 第二轮裁定（消融实验之后）

### R-6 · AC-006 改成**三条判据**（Dev 指出宽口径会被"同一种谓词刷量"刷高，我认）

| # | 判据 | 阈值 | 抓什么 | 内置 | skill | 最小契约 |
| --- | --- | --- | --- | --- | --- | --- |
| 1 | 归属/包含类占比 | **> 5%** | 有没有落到结构上 | 1.19% ❌ | 12.81% ✅ | 29.70% ✅ |
| 2 | **谓词种类 / 关系数** | **≥ 0.33** | 是不是同一条刷量 | 0.43 ✅ | 0.36 ✅ | **0.24 ❌** |
| 3 | **`doc merge` 冲突数** | **= 0** | 关系自相矛盾 | 0 ✅ | **0 ✅** | **15 ❌** |

**裁定：三条同时满足才算过。** 只有 skill 臂三条全绿。

**为什么必须加第 2、3 条**：Dev 的消融实验里，最小契约靠「包含字段 92 + 包含指标 90」把第 1 条刷到 29.70%，
**但它是同一条谓词刷量、还抽出了 15 条自相矛盾的关系**。
⇒ **单指标判据会被"优化的对象"反过来利用**——这是判据设计的通病，不是这一条特有。

### R-7 · R-3「未能分离模型」：接受，结论永久降级

pi 侧只有 MiniMax（4 个），我们的端点没有 MiniMax ⇒ **两边无交集**。Dev 的反向尝试与报错都贴了（`Unknown modelId` / `-32601`）。

**裁定**：
- 接受「**未能分离**」
- 结论永久写成：**「ACP + MiniMax-M2.7 优于 内置 + deepseek-v4.1-flash」**
- ⛔ **不许**说成「我们的 skill 更优」「ACP 通路本身更优」
- `PI_HOME` 独立目录试验**暂不做**（会污染宿主机全局 pi 配置，收益不抵风险）；记录为可选路径

### R-8 · 但消融实验给了一个**真正的发现**，要改 skill

Dev 的最小契约在**归属/包含类占比上反超**，原因是它大胆抽了「**包含字段**」「包含指标」这类边。

**这不是刷量的全部真相**——对**结构化文档（字段表）**来说，「实体 包含 字段」**本来就是正确的关系**。
我的 skill 把模型教得**过于保守**了（关系 989 → 648，归属占比 32.76% → 12.81%）。

⇒ **裁定：skill 增加「结构化文档（字段表）专用判据」一节**，明确：
- 字段表里 `实体 包含 字段` / `枚举 取值包含 X` 是**合法关系**，不算泛动词
- 但仍要求：谓词要具体（`包含字段` ≠ `包含`）、每条要有 quote（字段行原文）
- 仍然禁：`使用/读取/写入/处理/进行/支持` 这类跨语料通用的泛动词

### R-9 · R-4 的两条：认可 + 一处要改

| 项 | 裁定 |
| --- | --- |
| `OUTPUT_PROTOCOL` **保留** | ✅ 对——skill 把形状委托给"调用方运行时指令"，那段就是它 |
| `span` 由程序回填（字节）、模型自报被忽略 | ✅ 对（模型报字符、程序存字节；且模型常按整篇数） |
| **skill §六 要求模型"自检 span"** | ⚠️ **我改** —— 在 ACP 通道上这条对模型无意义，改成"若调用方要求你给 span 才自检" |

### R-10 · 数字会变，别拿旧表对

新 skill 让模型**更少发关系、更少发「包含X」**（989→648）。这是**有意的收紧**，不是退化。
⇒ 旧对照表（32.76%）作废，**以 R-6 三条判据的新表为准**。
