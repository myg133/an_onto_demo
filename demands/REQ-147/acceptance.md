## 三 · 复验裁定（Dev 交付后）

### R-1 · AC-006 的判据**是我的错**，改成"归属/包含类占比 > 5%"

我写的是「`belongs_to` 命中率必须 > 0」。Dev 查出：**这条字面判据结构性不可满足**——

`STRUCTURAL_PREDICATES`（`doc_ingest.rs:145`）里有 `belongs_to`，**谓词闸在计数之前就把它丢了**，所以它永远出现在不了"活下来"的统计里（`belongs_to_share.alive` 恒 0）。而 skill 要求中文名词化谓词，模型不会吐英文字面量。

**裁定：改口径为「归属/包含类谓词占比 > 5%」**

| 口径 | 内置 | ACP |
| --- | --- | --- |
| 严格归属类（归属/属于/所属/隶属） | 0.40% | 0.51% |
| **含「包含」类（宽口径）** | **1.19%** | **32.76%** |

**为什么接受宽口径**：它测的是"关系有没有落到**结构**上"（包含字段 / 取值包含 / 归属采集项），
而这正是我们要的——**能映射到实体-属性/实体-实体的边**。27 倍的差距不是噪声。

**但真正的价值证据是另三组数字**（这些才是本需求的理由）：

| 指标 | 内置 | ACP | 变化 |
| --- | --- | --- | --- |
| **泛动词占比**（使用/读取/写入/处理/进行/支持/融合/调用/获取） | 18.65% | **1.31%** | **-93%** |
| **关系两端都是概念**（不悬空） | 26.2% | **96.4%** | 3.7× |
| quote 校验通过率 | 100%（但它几乎整段照抄标题） | **98.7%**（**31 条编造/拼接被机器丢掉**） | — |

### R-2 · AC-003 的确定性：**接受"有条件成立"，但必须显式化**

Dev 实测：run1 有 2/95 块传输级失败 ⇒ 那 2 块不进缓存（REQ-116 纪律：失败要能重试）⇒ run2 重调、输出变。

**裁定：采纳 Dev 的 A + C**

| 项 | 内容 |
| --- | --- |
| **A** | 屏幕上**必须**报："本轮 N 块失败，重跑会重调这 N 块 ⇒ 产物可能变化"（用 `stats.failed_calls`，零语义改动） |
| **C** | 新增 `--strict-deterministic`：本轮 `failed_calls > 0` ⇒ **exit≠0 且不产出产物** |

**⛔ 不采纳 B**（让失败也进缓存）：那会把**一次瞬时故障变成永久结论**，比不确定性更糟。

**判据改写**：AC-003 的成立条件 =「**首轮所有块都有回答**」；`--strict-deterministic` 下**无条件成立**（否则不产出）。

### R-3 · 对照实验**必须分离模型变量**（这条是硬要求）

Dev 自己指出：ACP 侧是 `pi-acp` + `MiniMax-M2.7`，内置侧是 `deepseek-v4.1-flash`。

> **所以"ACP 更好"里混了"模型更强"这个变量。skill 的价值未被证明。**

**裁定：必须补一组同模型对照**（用 `session/set_config_option` 把 pi 切到 deepseek）。

若切换失败 ⇒ **如实报"未能分离"**，并在结论里降级为「ACP+MiniMax 优于内置+deepseek」，**⛔ 不许说成"我们的 skill 更优"**。

### R-4 · skill 与解析器形状不一致：**改 skill，不加第二份契约**

Dev 的处理是"在 system prompt 末尾追加 OUTPUT_PROTOCOL 做仲裁，skill 一个字不改"。

**问题**：这等于**同一条要求写了两份**（skill 里说 JSONL，运行时说 JSON 对象）——违反我们刚立的「一个行为只在一个文档定义」。

**裁定：我来改 skill**——§一 改成"**语义契约**（抽什么、证据怎么给），**输出形状由调用方的运行时指令指定**"。这样 skill 保持通用，且不再与任何通道冲突。
