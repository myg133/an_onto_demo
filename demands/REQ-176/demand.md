# REQ-176 · 发布闸的**业务词白名单**（部署级配置，默认不放松）

- 优先级：P1（客户本体里出现「业务词 = 建模术语」时无法发布）
- 状态：已就绪
- 触发：2026-10-28 客户本体里有 `display_name = "evidence"`（审计/取证域的正常业务词）⇒ 发布闸 C6 拒绝整份客户视图 ⇒ 项目 500 无法加载

## 一 · 问题

客户视图的建模术语闸（`src/domain/view.rs::scan_modeling_terms`）是一把**通用**尺子：
`evidence` / `key` / `pk` / `主键` / `证据` … 一出现就拒。

但它分不清「建模术语泄漏」与「业务词恰好同名」。审计/取证域的实体叫 **evidence** 是合理的，
改成中文「证据」更糟（CJK 术语是**子串**匹配，一样命中）。

⇒ 客户要么改业务命名（不可接受：业务词由客户领域决定），要么闸门放水（不可接受：闸门是防线）。

## 二 · 要做的：部署级**业务词白名单**

新增 `--term-allowlist <file>`（`query serve` 与 `ontok ontology export` 都支持）：

```
# 每行一个词，# 开头为注释
evidence
```

### 语义（必须精确）

1. 扫描仍由 `scan_modeling_terms` **一份实现**完成（⛔ 不许在别处再写一份判据）
2. 白名单在**闸门层**过滤：`hits - allowlist`；**剩下的空** ⇒ 放行
3. 白名单里的词被豁免时，**必须留痕**：启动打印一条 + 每次豁免打一行日志（词条 + 出口）
   ⛔ 不许静默放行 —— 这是"看得见的放宽"，不是"没有闸门"
4. 文件不存在 / 读不出 / 行长不合法 ⇒ **启动失败**（fail-closed），⛔ 不许当作空表继续跑
5. 不给 `--term-allowlist` ⇒ 行为与今天**逐字节一致**

## 三 · 验收

| # | 判据 |
| --- | --- |
| AC-001 | 不给 flag：含 `evidence` 的视图仍被拒（行为不变） |
| AC-002 | 白名单含 `evidence`：同一份视图**放行**（真进程），且日志里有一行点名 `evidence` + 出口 |
| AC-003 | 白名单含 `evidence`，视图里还有 `主键` ⇒ **仍然拒**，且错误消息只列 `主键`（不列 evidence） |
| AC-004 | 白名单文件不存在 / 有非法行 ⇒ **启动失败**，错误消息点出文件与行号 |
| AC-005 | `ontok ontology export` 与 `query serve` 用同一份白名单文件 ⇒ 判定一致（同一份产物） |
| AC-006 | 白名单里塞一个**不在词表里**的词 ⇒ 启动时**警告**"这行没意义"，但不失败（防手滑） |

**红绿自证**：把"闸门层过滤"那一步注掉 ⇒ AC-002 红；恢复 ⇒ 绿。
