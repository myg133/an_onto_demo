## 问题：守卫是「字面量探针」，**加一行诱饵**就能骗过

REQ-070 的封条接线守卫断言「`seal_evidence_line` 调用仍在位」——
但它判的是**源码文本里有没有那个字面量**。

QA 的三级实验：

| 绕过形态 | 结果 |
| --- | --- |
| 直接把调用摘掉 | 🔴 红 |
| 挪到中转 helper 里 | 🔴 红 |
| **加一行字面量诱饵 + 影子函数** | 🟢 **req070 7/0 全绿** |

**全仓交叉验证**：req065 / 058 / 068 / 069 / 075 / `test_review_view` / lib
**118/0 全部无感**；**再叠加「语料外载荷丢失」的复合攻击，依然全绿**。

⚠️ QA 的判断：**是真缺口，且比 Dev 自陈的更宽** ——
**不是「摘掉调用」，是「加一行诱饵」**。

**这与 REQ-075 已修好的那一格是同一个病**：
「文本长得对」就足以骗过，而判别力挂在文本上。
REQ-075 为**类别轴**换了行为扫描网，**但封条接线这一格没动**。

---

## AC-001 · 封条接线必须由**行为**判定，不是文本

- 预期结果：断言「**载荷封条确实生效**」（例如：喂一个退化形态、
  断言渲染结果里带上了载荷指纹），而不是断言「某个字面量出现在源码里」
- 类型：测试有效性
- ⚠️ **照 REQ-075 已落地的做法做**：
  直接调用被测函数，判别力从「文本对不对」变成「**行为对不对**」

## AC-002 · 不得引入新的**假阳性面**

- 预期结果：语义保持的重构（改名、内联、挪 helper）**必须仍绿**
- ⚠️ REQ-075 的扫描网有一处**有意的**假阳性面：
  期望值用测试侧的 `to_string()` 独立计算 ⇒ 若生产改 `to_string_pretty` 会假红。
  QA 判「**是有意为之且已登记 ⇒ 不扣分**」。
  **本条沿用同一取舍，不要因为怕假红而退回文本探针。**

## AC-003 · 判别力自证

| 变异 | 预期 |
| --- | --- |
| M1 直接摘掉封条调用 | **必须变红** |
| **M1′** = **M2**（挪进中转 helper）**且真的从链上摘掉**（即 M2drop） | **必须变红** |
| **M3 加字面量诱饵 + 影子函数（QA 实测存活的那一格）** | **必须变红** ⭐ |
| M4 M3 **叠加**语料外载荷丢失 | **必须变红** |
| M5 语义保持的重构 | **必须变绿** |

⚠️ **M3 是本条灵魂**：它复现的正是 QA 实测存活的那一格。
**M4** 是复合攻击——两处独立缺口叠在一起时是否仍然有牙。

### ⛔ 2026-10-11 修正：BA 原稿的 **M2 行已删**（与 AC-002 自相矛盾）

**BA 原稿同时写了**：AC-002「**挪 helper 必须仍绿**」+ AC-003「M2 = 挪 helper ⇒ **必须变红**」。
**同一种变异，一条要绿一条要红 —— 是 BA 写错了。**

**QA 裁决：M2 绿是对的**，并给出**三段实测**（不是推理）：

| 观测 | 结果 |
| --- | --- |
| M2（纯搬迁，语义不变） | 🟢 7/0，exit 0 |
| **M2 + M6**（搬迁 + 规则②忘转义） | 🔴 6/1，红在「修复形态」那条 |
| **M2drop**（搬迁后**真的摘掉**封条） | 🔴 6/1，红在「承重性」那条 |

⇒ 若封条在搬迁中掉了，M6 的改动**根本无处可观测、不可能红**
⇒ **搬迁后封条仍在承重，且可从新调用点观测到**。

**QA 把它推到更一般的一层**：判据是**渲染输出的纯函数** ⇒
任何**不改输出**的重构真假值不变 ⇒ **任何**行为判定都判 M2 绿。
QA 还试过把判据升级成「**传递性污点**」（封条返回值必须流入输出），**同样判不出 M2**。

**冲突不在措辞，在「判据的局部性轴」上** —— BA 的两条 AC 正好占住轴的两端。
⇒ **已把 M2 改写成 M1′**，它是可执行的。

⚠️ 另：**M5 的「改名仍绿」需限定到「本条判据」** ——
QA 实测旧守卫对纯改名的判决是**任意的**（改名含原子串则绿、不含则红），
且新判据那一格的红来自**既有** doc 守卫（基线就有），不是本条判据。
