# 真库联调 runbook（本机 podman + 真服务 + 真浏览器）

> 写给**下一个要跑端到端的人**。今天（2026-10-27）我们花了半天才发现「本机其实有库」，
> 这份文件就是让那半天不用再花。
> 环境事实与踩坑都来自实测，不是推测。

---

## 〇 · 前提

| 项 | 值 |
| --- | --- |
| 数据库 | **podman 容器 `ontok-pg`**（`docker.io/library/postgres:16`，`--network host`） |
| 宿主可达 | `127.0.0.1:5432`（实测 TCP 通，不是只能容器内访问） |
| 口令 / 用户 | `postgres` / `postgres` |
| 建库 | `podman exec ontok-pg psql -U postgres -c "CREATE DATABASE <会话专用库>"` |

⛔ **不要**新建容器、⛔ 不要在 WSL 里装库、⛔ 不要 `podman rm` 那个容器（它有历史数据）。
**一个会话一个库**（`ontok_lion_dev` / `ontok_qa_req160` / `req160_lion_verify` 都是这么来的）。

## 一 · 环境变量（四条，缺一不可）

```powershell
podman exec ontok-pg psql -U postgres -c "DROP DATABASE IF EXISTS demo_e2e"
podman exec ontok-pg psql -U postgres -c "CREATE DATABASE demo_e2e"

$env:ONTOK_TEST_DATABASE_URL = "postgresql://postgres:postgres@127.0.0.1:5432/demo_e2e"
$env:ONTOK_DATABASE_URL      = $env:ONTOK_TEST_DATABASE_URL
$env:ONTOK_SECRET_KEY        = "0123456789abcdef0123456789abcdef0123456789abcdef0123456789abcdef"  # 64 hex
$env:CARGO_TARGET_DIR        = "D:\MyCodes\AI\an_onto_demo\.local\cargo-develop"                    # 复用热 target
```

⚠️ `ONTOK_SECRET_KEY` 不是可选的：`review open` / `console` 无条件持有 DSN 加密器，缺它**拒绝启动**。

## 二 · 造一个可打包的版本（构建端）

```powershell
ontok-builder project new --name demo-e2e          # 项目名：小写/数字/连字符/**下划线**，2..63
ontok-builder version new --project demo-e2e        # ⇒ v1
ontok-builder import --file out/proposal.json       # 提案 JSON（注意：**没有 --project**，项目从文件里读）
ontok-builder review decide --proposal p1 --project demo-e2e --accept-all   # ⚠️ 仅造数据用
ontok-builder proposal apply --proposal p1 --project demo-e2e               # ⇒ v2 + 快照
```

⚠️ `import` 读的是提案里的 `project` 字段。改名要改文件（不要手改 manifest/包，重新 `pack`）。

## 三 · 打包 + 自检

```powershell
ontok-builder bundle pack --project demo-e2e --version 2 --out out/demo.ontokbundle --built-at 2026-10-27T04:00:00Z
ontok-builder bundle verify --file out/demo.ontokbundle
#   0 = 通过；2 = 包不合规（会点名 code + path + 改法）；1 = 环境/IO
```

**确定性**：同 `--built-at` 打两次 ⇒ sha256 必须相同。
**不接受**被 `zip -r` / Python `ZIP_DEFLATED` 重压过的包（`bundle.unsupported.compression`，只认 method 0）。

## 四 · 起真服务（本地审核台）

```powershell
ontok-builder review open --project demo-e2e --no-browser --token-ttl 30m
```

打印：URL（`http://127.0.0.1:<内核分配端口>/`）、项目与版本、**一次性 admin 口令**（68 字符，只出现一次）。
⛔ 口令不进 URL、不落盘、进程退出即失效。

## 七 · 踩过的坑（都是实测，不是告诫）

| # | 坑 | 现象 / 破解 |
| --- | --- | --- |
| 1 | **共享 `CARGO_TARGET_DIR` 会串测试二进制** | 变异副本跑出「假绿」：cargo 复用了原仓的测试 exe（内嵌 `CARGO_MANIFEST_DIR`）。破解：副本 `Cargo.toml` 改版本号，或换独立 target；自查：测试 exe 里搜 `CARGO_MANIFEST_DIR` |
| 2 | **同一 target 也会串被测二进制** | `debug/ontok-builder.exe` 同一输出路径，fingerprint 没变就不重写 ⇒ 你以为跑新的，实际跑旧的。破解：删 exe + `touch` 源文件再 build，并用**只有新提交才有的字符串**验身 |
| 3 | **还原备份会让 mtime 变旧** | cargo 认为没变、继续用变异版。`touch` 后重编 |
| 4 | **项目名 pattern** | 2026-10-27 起允许 `_`（`^[a-z0-9][a-z0-9_-]{1,62}$`）；大写/空格/斜杠/点/`..` 仍拒。**历史项目名带下划线，别当成脏数据** |
| 5 | `credential.suspect` 误报 | 快照里有业务列叫 `password` 会触发；判据已收紧成「键名 + **非空字面值**」。真凭据（`"password":"hunter2"`）仍告警 |
| 6 | `review open` 找不到 `console` | console 在 **`ontok-builder`** 上（REQ-152 拆二进制时搬的）；`ontok` 只有 `query` / `serve` / `mcp-server` |
| 7 | 两人同时往 `code/` 里 merge | 会读到对方的**半合并态**、报假红。**写操作必须串行**：先发「我要动 `code/`」，做完发「完成，`develop`=X」 |
