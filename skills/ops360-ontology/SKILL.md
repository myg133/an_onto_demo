# Ops360 本体使用规范


## 〇 · 连接信息**由部署注入**（本文件不含地址与口令）

⛔ **这份 skill 里没有、也不许有** `base_url` 和 `token`。

| 为什么 | 说明 |
| --- | --- |
| skill 是**共享资产** | 会打包、分发、被复制到多个 Agent 目录 |
| 地址**每套部署一个** | UAT / PROD / 客户私有环境各不相同 |
| token 写进来 = **泄漏** | 进 git、进分发包、进日志截图 |

### 运行时从哪读（按优先级）

| # | 来源 | 变量/字段 |
| --- | --- | --- |
| 1 | **MCP server 配置**（推荐） | 平台侧 `mcpServers` 里的 `url` + `headers` |
| 2 | 环境变量 | `ONTOK_BASE_URL`（如 `https://an-onto.example.com`）、`ONTOK_TOKEN` |

平台用 MCP 时，配置长这样（**token 由平台注入，不落在 skill 里**）：

```json
{
  "mcpServers": {
    "ontok": {
      "type": "sse",
      "url": "${ONTOK_BASE_URL}/mcp",
      "headers": [{ "name": "Authorization", "value": "Bearer ${ONTOK_TOKEN}" }]
    }
  }
}
```

### 拿不到连接信息时怎么办

⛔ **不要猜地址**（不要试 `localhost`，不要试上一套环境的 URL）。
✅ 明确说：「当前运行环境没有注入 `ONTOK_BASE_URL` / `ONTOK_TOKEN`，无法访问本体服务，请联系部署方。」

> 猜一个地址最坏的结果不是报错，而是**连到别的环境**——那会把别人的数据当成本租户的答案。

## 一 · 你手上是什么

一份 **OWL 本体**（`ops360.ttl`），描述 Ops360 云运维体系里的：

| 维度 | 数量 |
| --- | --- |
| 类（概念） | 20 |
| 关系（对象属性，正反成对） | 10 |
| 属性（数据类型属性） | 47 |
| 业务口径 | 10 |

**它没有实例数据。** 没有"某个账号下有几台机器"，也没有"上个月花了多少钱"。

## 二 · 怎么读

```
<https://ontok.local/ops360#>
```

| 元素 | 含义 |
| --- | --- |
| `owl:Class` + `rdfs:label@zh` | 一个业务概念 |
| `owl:ObjectProperty` | 概念之间的关系；带 `owl:inverseOf` 的反向边 |
| `owl:DatatypeProperty` | 概念的属性（如「备份覆盖率」） |
| `rdfs:comment` | 语义说明（有些约束只能写在这里） |
| `:业务口径` 类 | 10 条业务口径，每条一个属性，定义在 `rdfs:comment` |

## 三 · 回答规则（硬）

### ✅ 应当回答

- 「有哪些概念/类」→ 直接列 `owl:Class`
- 「X 和 Y 什么关系」→ 查 `ObjectProperty` 的 domain/range + `inverseOf`
- 「某口径怎么算」→ 读 `:业务口径__<名字>` 的 `rdfs:comment`

### ❌ 必须拒绝

- 任何**具体数值**问题（数量、金额、占比、趋势）⇒ 回答：
  > 「这套本体只描述概念与关系，不含实例数据；具体数值需要接业务数据库。」
- 任何**时间范围**问题（上个月、昨天、最近 7 天）⇒ 同上
- 任何**预测/建议**（"要不要扩容"）⇒ 本体不含决策规则

### ⚠️ 转述限定

- 属性类型有 21 个是**启发式推断**（文档没写）。被问到字段类型时，说明"文档未明确"。
- 关系**没有 join 列**：不能说"这条关系对应数据库里哪两个字段"。

## 四 · 反面例子（会被判错）

| 用户问 | ❌ 错误回答 | ✅ 正确回答 |
| --- | --- | --- |
| 「有多少台 RDS？」 | 「共 37 台」 | 「本体里有『关系型数据库实例』这个类，但**不含实例数量**；需要接库查询。」 |
| 「CDN 上个月多少钱？」 | 「约 1200 元」 | 「『CDN 总流量』有口径定义，但**没有数据**，无法给金额。」 |
| 「备份覆盖率达标吗？」 | 「达标，92%」 | 「『备份覆盖率』的定义是『已备份资源/应备份资源』；**具体数值需要数据源**。」 |

## 五 · 溯源

如果被问「这条关系是从哪来的」：

1. 在 `assertions.jsonl` 里搜概念名
2. 取 `evidence.quote`
3. 那是**原文逐字片段**

**如果没有 quote，就不要声称它是从文档来的。**
