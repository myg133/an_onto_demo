# Ops360 本体 · 项目专用说明

> **这份文件只讲"这套部署里有什么"，不讲"怎么干活"。**
> 怎么调接口、怎么读回执、错误怎么处置 —— 见 **`ontok-query`** skill。
>
> 两份是**配套关系**，不是二选一：
>
> ```
> ontok-query      → 流程（第 0 步 health、第 1 步取 TTL、第 2 步 catalog…）
> ops360-ontology  → 内容（这个本体里具体有哪些概念、哪些问题必须拒绝）
> ```

---

## 一 · 这个本体是什么

Ops360 云运维体系的本体，从 **16 篇文档**（技能说明 + 配置 + 巡检报告）抽取而来。

| 维度 | 数量 |
| --- | --- |
| 类（业务概念） | **20** |
| 关系（对象属性，正反成对） | **10 条** |
| 属性（数据类型属性） | **47** |
| 业务口径 | **10** |

**规模小是刻意的**：这是从原文归并后的结果，不是把文档片段直接倒出来。

---

## 二 · 部署模式（**重要**）

这套部署是 **`ontology-only`（本体模式）**：

```
mode = "ontology-only"
⇒ 只有本体，没有业务库
⇒ SPARQL 恒 503 NO_DATA_SOURCE（不是故障，别重试）
```

**判断方法**：`GET /api/health` 的响应里有 `"mode": "ontology-only"`。

## 三 · 概念分区（20 个类）

| 分区 | 概念 |
| --- | --- |
| **资源** | 云资源 · 关系型数据库实例 · 对象存储 · CDN 域名 · 安全组 · 安全组规则 · SSL 证书 · 云托管证书 |

> 具体名字以 `GET /api/catalog` 返回的 `display_name` 为准——**别按这张表猜**。

## 四 · 业务口径（作为 `:业务口径` 类的属性）

口径的定义**在 TTL 的 `rdfs:comment` 里**，照抄，别自己发挥。

本部署包含的 10 条：备份覆盖率 · 日均费用 · 可用余额 · 待续费资源数 · 未恢复告警数 · 严重告警数 · 资源总数 · CDN 总流量 · 对象存储容量 · 近 30 天巡检覆盖资源数

> 每条口径的**具体算法**读 TTL，不要用常识补全。

## 五 · 回答规则（硬）

### ✅ 应当回答

- 「这套运维体系里有哪些概念 / 怎么关联」
- 「某条口径怎么算」
- 「A 和 B 是什么关系」

### ❌ 必须拒绝（这套部署没有数据）

| 用户问 | 正确回答 |
| --- | --- |
| 「有多少台 RDS？」 | 「本体里有『关系型数据库实例』这个类，但**这套部署不含实例数据**。」 |
| 「CDN 上个月花了多少钱？」 | 「有『CDN 总流量』这个口径的定义，但**没有数据**，给不出数值。」 |
| 「备份覆盖率达标吗？」 | 「『备份覆盖率』的定义是『已备份资源/应备份资源』；**具体数值需要数据源**。」 |
| 「要不要扩容？」 | 「本体不含决策规则。」 |

**关键**：拒绝时**不要只说不**，要给出「本体里有什么」——用户至少能知道这个系统里存在这个概念。

## 六 · 已知限制（照实说）

| # | 限制 |
| --- | --- |
| 1 | 47 个属性里 **21 个类型是推断的**（文档没写），标为 `string` |

被问到这些时**如实说明**，不要假装确定。
