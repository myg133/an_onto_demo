# 通用抽取契约

> 你的唯一任务：**从文档里取出「概念」和「概念之间的关系」，并给每一条配上原文逐字引用。**
> 你不是在写摘要，也不是在解释文档。**你只做抽取。**

---

## 一 · 你要产出什么（语义）

| 产出 | 含义 |
| --- | --- |
| **概念** | 一个名词性实体（判据见 §二） |
| **关系** | 两个概念之间的一条稳定关系（判据见 §三） |
| **证据** | 每条概念/关系都必须配一段**原文逐字引用** |

⛔ **本文件不规定输出格式。** 输出是 JSONL、单个 JSON 对象、还是别的形状，
**由调用方在下发的运行时指令里指定**——照那个来，别按本文件猜。

**不管什么形状，这三样必须齐全**：

| 项 | 规则 |
| --- | --- |
| `quote` | **原文里逐字存在**的片段（复制粘贴，⛔ 不许改写、不许省略号拼接） |
| `span` | **仅当调用方要求你给时**才输出：`quote` 在该块里的起止位置；对不上就说明 `quote` 是编的。（有些通道由程序回填，⛔ 别为了凑 `span` 去改 `quote`） |
| 名字 | 概念名**用原文的说法**（⛔ 不翻译、不缩写、不统一同义词） |

⛔ **没有 `quote` 的条目一律不要输出。** 宁可少一条，不许编一条。

## 二 · 什么算「概念」

**算**：

| 判据 | 例子（抽象） |
| --- | --- |
| 名词性实体，能被反复指代 | 「<某类对象>」在多段里被提到，且指同一个东西 |
| 有定义句 / 属性描述 | 「<术语>是指……」或「<术语>包括……」 |
| 是关系的端点 | 别的句子说「X 属于 Y」，X 与 Y 都该被抽出来 |

**不算**：

| 不算 | 为什么 |
| --- | --- |
| 动词、形容词 | 那是动作/性质，不是实体 |
| 一整句话 | 概念是**名词**，不是描述 |
| 只出现一次的修饰性词组 | 没有独立语义地位 |
| 示例里的具体取值 | 「例如 A、B、C」里的 A/B/C 是**取值**，不是概念 |
| 文档的结构词（"简介""步骤""注意"） | 那是排版，不是领域概念 |

---

## 三 · 什么算「关系」

关系必须同时具备**三样**：

| 要素 | 说明 |
| --- | --- |
| **方向** | 从哪个概念到哪个概念（单向，不要"两者相关"） |
| **具体谓词** | 见下表 |
| **两端都在概念集合里** | 端点不存在 ⇒ ⛔ 不输出该条 |

**谓词要求**：

| ✅ 可以 | ⛔ 不可以 |
| --- | --- |
| 名词化：「归属」「包含」「依赖」「被引用」「上限为」 | 泛动词：**「使用」「读取」「写入」「处理」「进行」「支持」「融合」「调用」「获取」** |
| 明确的动作短语：「挂载到」「绑定到」「由……产生」 | 无方向的词：「相关」「有关」 |
| 有依据的语义关系 | 凭常识补的：「两者都是资源，所以相关」 |

**为什么禁泛动词**：它们几乎出现在每句话里，抽出来等于没抽——
它们不构成**两个具体概念之间**的稳定关系。

### ⭐ 结构化文档（字段表 / 数据字典）的例外

如果文档是**字段表**（形如 `| 字段 | 类型 | 说明 |` 的表格），下面这类关系**是合法的**，不算泛动词：

| 合法关系 | 例子 | 为什么合法 |
| --- | --- | --- |
| **实体 包含 字段** | `<实体> 包含 <字段名>` | 字段表就是在描述这个 |
| **字段 取值包含 X** | `<字段> 取值包含 <枚举值>` | 枚举是文档明确列出的 |
| **字段 引用 另一实体** | `<字段> 引用 <另一实体>` | 类型列写了 `Array of X` / `X` |

**但仍然要求**：

| 要求 | 说明 |
| --- | --- |
| 谓词要**具体** | 用「包含字段」「取值包含」「引用」，⛔ 不要只写「包含」 |
| **每条都要有 quote** | 引那张表的**那一行原文**（如 `| InstanceId | String | 实例ID。 |`） |
| **⛔ 不要拍平嵌套** | `A.B.C` 是字段路径，**不要**为了凑关系把它拆成 A→B→C 三条 |
| **⛔ 不要给同一实体刷同一谓词** | 同一个（实体, 谓词）刷出 90 条，等于没抽 |

> **自检**：如果你的关系里同一种谓词占了 1/3 以上，说明你在把「字段表」抄成关系——
> 这时应该**减少关系、提高多样性**（谓词种类 / 关系数 应 ≥ 1/3）。

### ⭐⭐ 关系动词：**从字典里选**（REQ-157）

关系的谓词**不是自由文本**：它来自一张受控字典 `relation-verbs.json`（随仓库发布，`ontok-builder relation verbs check` 用同一份字典校验）。**只准从下面 16 个主键里选**：

| 主键 | 中文标签 | 什么时候用 |
| --- | --- | --- |
| `belongs_to` | 归属于 | 从属：子对象属于父对象（"X 属于 Y"） |
| `attached_to` | 挂载于 | 挂载 / 装载（磁盘挂到实例、网卡挂到实例） |
| `binds_to` | 绑定到 | 绑定（弹性 IP 绑到网卡、监听器绑后端、监听器绑证书） |
| `references` | 关联到 | 引用另一份配置 / 对象 / 规则 |
| `notifies_via` | 通知到 | 通过某个通道通知（告警策略 → 通知模板） |
| `applies_to` | 适用于 | 策略 / 规则适用于某类对象 |
| `forwards_to` | 转发到 | 把请求 / 流量转发到目标 |
| `targets` | 指向 | 直接指向某个后端 / 目标 |
| `bills` | 计费到 | 账单 / 费用记到某个资源 |
| `based_on` | 基于 | 由某个模板 / 镜像 / 基础对象产生 |
| `deployed_to` | 部署于 | 部署在某台实例 / 环境上 |
| `has` | 拥有 | 真正的拥有（⛔ 不是"有个字段"） |
| `depends_on` | 依赖 | 运行期依赖（没有它就不能工作） |
| `records` | 记录了 | 日志 / 记录类对象记录了某件事 |
| `derived_from` | 算自 | 由另一份数据算出来 |
| `contains` | 包含 | ⚠️ **已弃用**（泛词）；只有确实没有更具体说法时才用，构建会告警 |

**同义写法用别名，⛔ 别自己造**——写别名会被自动归一到主键：

| 你可能会写 | 归一成 |
| --- | --- |
| `belong_to` · `owned_by` | `belongs_to` |
| `attaches_to` · `attached` · `mounts_to` | `attached_to` |
| `binds` | `binds_to` |
| `refers_to` | `references` |
| `notifies` | `notifies_via` |
| `applied_to` | `applies_to` |
| `forwarded_to` | `forwards_to` |
| `billed_to` | `bills` |
| `deploys_to` | `deployed_to` |
| `depends` | `depends_on` |

⛔ **这些词一条都不许出现**（字典 `forbidden`，构建直接拒绝、退出码 4）：

```
uses · associated_with · related_to · involves · has_many · is_related
```

**拿不准时按这个顺序做**：

1. 先在上表里找**语义最接近**的主键：「X 使用 Y」真正的意思通常是 `depends_on` / `attached_to` / `references` 中的一个；
2. **同一件事只用一种动词** —— 别同时出现 `attached_to` 和 `attaches_to`；
3. 找不到就**放弃这条关系**：宁可少一条，不许造词；
4. ⛔ 不要发明 `uses_ssl_certificate` 这类复合动词 —— 动词是**词表**，具体性放在两端的**概念名**上。

> ⚠️ 与下一节「结构化文档的例外」的关系：那里允许的复合谓词（`包含字段` / `取值包含`）**不在字典里**。
> 字段表场景请用 `contains`（已弃用，会告警）或 `references`，或把「实体 → 字段」写成概念归属；
> ⛔ 不要为了凑字段表造新谓词。
>
> ⛔ 本表的**唯一事实源**是仓库根的 `relation-verbs.json`；加动词要**人审**，不要在抽取时临时扩表。

**每条关系都必须两个端点都在「概念」集合里**（本块或前文已抽出的）。端点不存在 ⇒ ⛔ 不输出该条。

## 四 · 证据规则（**最重要的四条**）

| # | 规则 |
| --- | --- |
| 1 | `quote` **必须是原文逐字子串**（机器会用它在原文里定位，定位不到该条作废） |
| 2 | `quote` **要包含判据本身**：判断"A 属于 B"就要引**说出这句话的那半句**，不是引标题 |
| 3 | 一条 `quote` **只支撑一条断言**；不要拿一句话抽五条不同的关系 |
| 4 | 引不到原文的结论 ⇒ **不要输出**（哪怕你很确定它是对的） |

---

## 五 · 禁则

| # | ⛔ 禁止 |
| --- | --- |
| 1 | **扩写/改写原文**，或把两处的话拼成一句当引用 |
| 2 | **合并同义词/别名**（「X」和「X 系统」是两条，留到后续对齐环节处理） |
| 3 | **把「示例」当「定义」**（"例如……"里的话不是定义） |
| 4 | **凭常识补关系**（文档没说就不许有） |
| 5 | **输出没有引用的条目** |
| 6 | **解释文档**（不要写"这段说明了……"，直接给断言） |
| 7 | **翻译或改写术语**（用原文说法） |

## 六 · 自检清单（输出前逐条过）

```
□ 每条都有 quote，且 quote 我能原样在原文里找到吗？
□ （**仅当调用方要求你给 span 时**）span 与 quote 长度对得上吗？（止 − 起 == quote 字符数）
□ 概念都是名词吗？有没有混进动词或整句？
□ 关系的两端都在我抽出的概念里吗？
□ predicate 里有没有「使用/读取/支持/进行」这类泛动词？
□ 有没有把示例里的取值当成概念？
□ 有没有把同义词合并成一条？
□ 有没有一条是"我知道但文档没说"的？
```

**任何一条打不上勾，删掉那条断言。** 少一条不会毁掉结果，编一条会。

## 七 · 常见错误的对照

| 错误 | 为什么错 | 正确做法 |
| --- | --- | --- |
| 把「步骤 1、步骤 2」抽成概念 | 那是流程结构 | 不抽 |
| 把「X 使用 Y」抽成关系 | 泛动词，几乎每句都有 | 找更具体的说法（「X 依赖 Y」「X 挂载 Y」） |
| 把一句话抽成三条关系 | 一条引用只支撑一条 | 分三处引用，或只留最明确的那条 |
| 把「例如 A、B」里的 A 抽成概念 | A 是取值 | 抽「A 所属的那类东西」 |
| 关系端点不在概念里 | 悬空关系 | 补抽该概念，或丢弃该关系 |
| 引用写「……详见上文」 | 不是逐字子串 | 引原句 |

> 你输出的每一条都要能被机器拿回去在原文里对上；对不上的，一条都不该有。

## 十 · 抽完之后：**交给人审核**（你的任务到此为止）

> 你是抽取方，不是审批方。**签字只能由人做。**

### 1 · 你的最后一步

```bash
ontok-builder review open --project <项目>
```

- 起一个**本地**审核台（只绑 127.0.0.1）、自动选端口、生成**一次性** admin token、打开浏览器
- 命令退出（Ctrl-C）即失效；⛔ token 不会出现在 URL 里
- **工具版本还没有这条命令时**（早于 REQ-160）：

```bash
ontok-builder console serve --bind 127.0.0.1:8899 --tokens <admin-tokens.json> --project <项目> --schema <schema.json>
```

  然后把 **URL + 该填的口令**交给操作人，让**他**在页面顶部填。

### 2 · 你要交给人的一句话（照这个说）

> 已抽取 N 条断言，写到了 `<路径>`（丢弃 M 条：`quote` 在原文里定位不到）。
> **请你**在审核台上逐条确认：**评审 → 应用 → 冻结**。我**不会**替你签。

### 3 · ⛔ 四条禁令（违反即等于伪造人签）

| # | 不许做的事 |
| --- | --- |
| 1 | ⛔ 替人执行 `review decide`（尤其 `--accept-all` 批量放行） |
| 2 | ⛔ 替人 `proposal apply` / `version freeze` |
| 3 | ⛔ 把「我判断这些都没问题」当成审核结论 —— 判断是人的事，你给的是**证据** |
| 4 | ⛔ 为了让数字好看而放宽 `quote` 校验（对不上就是没有证据，一条都不该留） |

### 4 · 为什么这条要写进 skill

抽取质量再好，**没被人看过就不能进查询上下文**（ADR-005 / REQ-107 的发布闸）。
