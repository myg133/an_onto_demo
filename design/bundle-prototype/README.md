## 二 · 安全性：我把话说透

你说"后面要能查看，所以安全性再看看"。**能查看 ⇒ 必须可解密存储**，这跟"只存 sha256"是互斥的。我的处理：

| 做法 | 为什么 |
| --- | --- |
| 存**两份**：`sha256`（鉴权热路径）+ `ciphertext`（查看冷路径） | 每个请求都解密太慢，且把密钥拖进热路径 |
| 与 **DSN 共用一套密钥**（环境变量） | 多一套密钥 = 多一个丢失点 |
| 查看端点 **admin only** + **每次写审计** | "能查看"的唯一补偿 |
| 加密挡**拖库**，审计挡**内鬼** | 两者都**不挡**"有 admin token 的人"——这是功能本身的固有代价，不是实现缺陷 |

**样机里能看到的两件事**：
1. 每次点「查看 key」，警示条里数字会涨（第 1 次、第 2 次…）—— 对应真实审计。
2. 弹窗底部写着"有 admin 的人都能看任意项目的 key"。

## 三 · 五步（现在都在弹窗里）

| 步 | 内容 | 关键约束 |
| --- | --- | --- |
| **1 建项目** | 项目名 / 备注 / **这把 key 给谁用**（必填） | 填 `cloud-resource` ⇒ **409 project.exists** |
| **2 上传包** | 上传区 → 组件清单（ontology/am/db + sha256 ✓） | 没上传就点下一步 ⇒ 拦住 |
| **3 配 DB** | 类型 + DSN + **测试连通性** | **不测通不让过**（AC-004）；DSN 含 `bad`/`timeout` 可演失败 |
| **4 解析** | 进度条 + 逐行日志 | 自动跑，跑完才允许下一步 |
| **5 激活** | 表格对比 v5→v6 + 「冻结并激活」 | 激活后才出一次性 key |
