# 构建包导入 · 静态样机

> **纯前端、零依赖、不连后端**。双击 `index.html` 即可在浏览器里点。
> 用来在写代码之前把「建项目 → 上传包 → 配 DB → 解析 → 激活」这条链路的**交互顺序**定下来。

---

## 一 · 看什么

打开后点右上角的 **＋**（就是截图红框那个位置），会依次走五步：

| 步 | 你会看到 | 要确认的点 |
| --- | --- | --- |
| **1 建项目** | 弹窗：项目名 / 备注 / **这把 key 给谁用**（必填） | 项目名的校验、必填项提示、`409 project.exists` 冲突提示 |
| **2 一次性 key** | 黄色虚线框，key 明文 + 警告 | **只在这一次出现**；页面刷新就没了 |
| **3 上传包** | 点一下模拟上传 → 组件清单（ontology / am / db）+ 每件的 sha256 ✓ | 清单是不是你想要的信息密度 |
| **4 配 DB** | 弹窗：类型 + DSN + 「测试连通性」 | 三种结果：成功 / `db.connect.auth` / `db.connect.timeout` |
| **5 解析 + 激活** | 进度条逐行日志 → 新版本 v6（未冻结）→ 「冻结并激活」 | **解析 ≠ 生效**；激活是人工一步 |

## 二 · 三个我特意做进去的判断

### ① 匿名看不到加号

点右上角「切换为匿名」→ **加号消失**。

建项目是**写操作**，而 Studio 现在是匿名的。如果对匿名可见，等于**任何人在你的部署上都能建项目**。

### ② key 只显示一次

黄色框里明说"关掉就再也看不到"。服务端只存 `sha256`。
（这条不是为难用户，是为了不让 key 泄漏在数据库备份里。）

### ③ 「解析」和「激活」是两步

进度条跑到 `解析成功 → 新版本 v6（未冻结）` 时，**对外还查不到**——必须再点「冻结并激活」。

理由：解析出错要能回滚；而且 `v5` 仍冻结可用，切回去就是一分钟的事。

## 三 · 模拟数据（都是假的）

| 项 | 值 |
| --- | --- |
| 项目 | `cloud-resource`（已存在 → 用它建会触发 409） |
| 本体 | v5 · 30 类 / 34 关系 / 752 属性 |
| 包 | `bdl_01H…` · ontology(30/34/752) + am(3 租户) + db(postgresql, requires_dsn) |
| 解析结果 | 新版本 **v6**（包里写的 seq 会被服务端重新分配） |
| DB 测试 | DSN 里含 `bad` → 口令错；含 `timeout` → 超时；其它 → 成功 |

## 四 · 和契约的对应关系

| 样机里的动作 | 契约里的端点（`BA/demands/REQ-159/demand.md` §五） |
| --- | --- |
| 建项目 + 发 key | `POST /api/projects` |
| 上传包 | `POST /api/projects/:p/bundles` |
| 组件清单 | `GET /api/projects/:p/bundles/:id` |
| 配 DSN | `PUT /api/projects/:p/database` |
| 测试连通性 | `POST /api/projects/:p/database/test` |
| 解析 | `POST /api/projects/:p/bundles/:id/import` |
| 冻结并激活 | `POST /api/projects/:p/bundles/:id/activate` |

## 五 · 明确没做的

| 没做 | 为什么 |
| --- | --- |
| 真实上传（拖拽文件） | 样机只验交互，不验解析 |
| 错误码全量演示 | 只演了 3 个最常见的（409 / auth / timeout）；8 个全量在契约 §十一-4 |
| 多项目列表 / 切换 | 属于 P1c 之后的活 |
| 移动端适配 | 内部工具，桌面优先 |
