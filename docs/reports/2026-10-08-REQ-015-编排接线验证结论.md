## 二、F3 · 「0 违规」不能当「阶段 2 已验证有效」的证据

QA 自造的 `VendorModelAgent` 跑出 **8 条违规、四类全中**：
```
t_dev:     UnknownColumn / UnknownTable / NoSource / UnknownExistingType
t_customer:（同上 4 类）
```
变异体 M3 摘掉 `verify_mappings` 后掉到 0 条 ⇒ 判据可杀。

**但 0 违规的成因是同义反复，不是「验过了没问题」。**

`rule_based.rs:131` `let table = key.clone();` + `:140` `ColumnRef::new(table, column)`，
其中 column 来自提案条目 —— 而提案条目就是用**同一份 schema** 现取的。
⇒ **被核对的那份声明，正是用被核对的那份 schema 生成的**，
`UnknownTable` / `UnknownColumn` / `NoSource` **结构上不可能发生**，key 双向核对同理恒真。

**换成真 agent（RN-2）这条推理立刻失效**：模型输出与 schema 无任何构造性关联。

> Dev 在测试注释里写了「这是个**阴性**结论」——这句话诚实。
> **但 CLI 措辞不诚实**：stdout 打「阶段1/2 : 91 组（成功 91 · 失败 0）」，
> 读起来像「验过了、没问题」，而结构上它不可能有问题。

- QA 明确**不采信**「更轻」的辩解：有人说「`extracted_by` 记的是『本轮由谁驱动』，按定义含 agent 参与，未必算撒谎」——
