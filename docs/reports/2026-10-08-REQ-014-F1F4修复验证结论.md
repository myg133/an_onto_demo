## 一、F1 · 把「作用域」与「上下文」分开

### 问题回顾

`infer_link` 靠 `known_tables` 在 `customers` / `customer_rebate` 之间消歧，而 `known_tables` 由**组内表**构建 ⇒ 组外的 FK 目标解不出来 ⇒ 属性名从关系推导的「所属客户」回落成注释里的「客户标识」。上一批 22/22 测试对该缺陷**完全失明**。

### 实现

```rust
// 组上多一份只读上下文
pub struct ExtractionGroup {
    pub schema: Vec<TableMeta>,        // 作用域：这一组要抽的表（未动）
    pub context_tables: Vec<String>,   // 上下文：全库表名，只供 FK 消歧
}

// 交给抽取器的那一份输入 —— 一对字段把两个角色表达死
pub struct ExtractionInput {
    pub scope: SchemaReport,           // 抽取器只遍历它
    pub context_tables: Vec<String>,  // 不遍历、不产出实体、不进统计
}
```

`src/extract/propose.rs:284` —— `known_tables = 作用域 ∪ 上下文`。
`extract()` 原样保留并委托空上下文，**既有 5 个调用点零改动**。

### QA 的作用域未放宽证据（机器级，非读注释）

- `known_tables` 的**全部消费点只有 2 处**，都是 `infer_link`（`propose.rs:356`、`:464`）
- `report.tables` 的**遍历点只有 1 处**：`propose.rs:299`
- `tables_seen` 只取 `report.tables.len()`：`propose.rs:268`
- **上下文只有表名** —— `context_tables: Vec<String>` 在**类型层面物理上无法携带列级元数据**。跨表抽属性在编译期就不可达。这是比文档约定强得多的保证。

### 「全量路径逐字节不变」的机器证明

把 `62edd26` 的 `extract()` 函数体与 HEAD 的 `extract_with_context()` 去签名后逐行 diff：
**唯一可执行差异** = 新增形参 + `known_tables` 的 `.chain(context_tables)`，其余 **249 行完全相同**。

### 反向对照为什么不是碰巧对

若反向对照无效（存在 plural/singular 候选兜底），QA 的 T3 会抓到「回落失败」。
真实库与自造库都实测到真实回落 ⇒ **判据有效**。

### 🔢 真实影响面（Dev 未测，QA 测出）

```
91 表逐表单组 → 42 条属性名因上下文改变 / 922 不变
样例: balances.customer_id              客户标识 → 所属客户
      customer_subscriptions.customer_id  ""      → 所属客户
```

**修复对真实库有效，但判据没覆盖真实库** —— 两条 F1 测试跑的是合成 fixture
（`t_dev` / `t_customer` 在真实 91 表库里**根本不存在**）。
合成 fixture 绿而真实库坏，是本项目栽过的同一类风险。→ 转 REQ-017②。

## 二、F4 · key 稳定性从注释变成机制

`verify_mappings` 的 `existing` 从 `HashSet` 改成 `HashMap<key, 已知显示名>`，四分支：

| 情况 | 违规 |
| --- | --- |
| `is_new=false` 但 key 不在清单 | `UnknownExistingType` |
| **`is_new=true` 但 key 已存在** | **`ExistingKeyDeclaredAsNew`（新增，补上 REQ-013 的静默洞）** |
| key 命中但 `display_name` 不同 | `ExistingDisplayNameChanged`（新增） |

沿用本文件纪律：**只报错不丢弃**。改名**合法但必须可见** —— 规格 §7.1 ④ 允许改 `display_name`，
但要保证它是进版本历史的显式事件，而非每轮静默漂移。

### QA 额外测出 3 个边界（Dev 未提）

- 占坑 + 改名同时发生 → **只报占坑**（match 臂优先级确定，不双报）
- `existing_types` 内 **key 重复 → `HashMap` 塌缩，`known` 取后者**，不报错
- 已知 `display_name` 为**空串**也会报改名 —— 这是「会吵」的第二个来源

## 七、QA 的变异验证方式（比派单要求的更干净）

任务禁止改 `src/`，QA **没有构造需要改源码的变异**，三类都有等价手段：

| 变异 | 手段 |
| --- | --- |
| A（去掉上下文合并） | `extract()` 传空上下文 ≡ `.chain(空迭代)` —— **行为等价**，无需改 `src/` |
| B（去掉改名检查） | 在测试文件里**复刻突变体**（纯函数可判定），喂同一输入 |
| C（去掉占坑检查） | 同上 |

> `.chain(空迭代)` 与不 chain 在 Rust 里语义完全相同，所以 `extract()` 就是变异 A 的**精确行为镜像** ——
> 这是比改源码更干净的验证方式。
