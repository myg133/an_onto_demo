### Q2 `mask_noncode()` 自己有没有洞？—— **有一个真洞（F-1），其余构造全部正确**

`mask_noncode` 在 `tests/test_connect_retry.rs:1067`，是本轮地基。逐项实测：

| 探针 | 构造 | 结果 | 判定 |
| --- | --- | --- | --- |
| **块注释嵌套** | `/* outer /* inner */ sleep( */` | 11/1 红 `:912:9` | 正确屏蔽 |
| **字符串含行注释起手符** | `"see http://x and sleep( here"` | 11/1 红 `:912:9` | 正确，未被当注释起手 |
| **字符串含块注释起手符** | 同机制 | 11/1 红 `:912:9` | 正确 |
| **C 风格转义引号** | `"he said \" sleep( ok"` | 11/1 红 `:912:9` | 正确，转义未提前闭合 |
| **字节串** | `b"sleep("` | 11/1 红 `:912:9` | 正确 |
| **`char` 字面量含斜杠** | `let c = '/';` | 11/1 红 `:912:9` | 正确、**无状态卡死** |
| **`'static` 生命周期** | `fn(&'static str)` + **真退避**（阳性对照） | 12/0 绿 | 未误判为字面量，真退避仍被认出 |
| **文档注释** | 未单测 | — | 与 `//` / `/*` 走**同一分支**（`:1104-1112`），嵌套块注释已覆盖该分支 |
| **raw string** | 见下 | **失控** | **真洞** |

**唯一的洞：raw string（F-1）。它有两个失效面，不是一个：**

- **面 a —— 失控 panic（探针 P7）**：`r#" msg " quoted sleep( here"#`
  里的引号让朴素扫描器提前闭合字符串；`mask_noncode` 的 `in_str` 状态**跨行不重置**
  （`:1078-1085` 只重置 `in_line_comment`），于是该行之后全文被屏蔽 → 配平括号消失 →
  `balanced_call` 在 `:446` panic「从第 145 个字节起的括号没有配平」。
  **方向是安全的（红），但失败模式失控**：判据不是给出结论，而是崩在扫描器里，
  报错信息「括号没有配平」会把人引向完全错误的方向。
- **面 b —— 真假绿（探针 P7d）**：把引号配成偶数（`let _ = r#"X " sleep( Y " Z"#;`），
  扫描器回到代码态且括号仍配平，但 `sleep(` **泄进了屏蔽视图** → `call_sites` 认定有退避 →
  **判据判绿**。此时真身是 **3 次尝试、零退避**。

**这一条直接证伪了 `mask_noncode` 文档里的话。** `tests/test_connect_retry.rs:1065` 写：
「对本判据已经够用（raw string 里的 `for` / `sleep(` 不会露出来）」——
**`sleep(` 确实会露出来，且露出来就产生假绿。**

**减轻因素（我独立核实，成立）**：封口表 `:31` 说「本仓实参无 raw string」——
四份判据实参（`src/db/apply.rs`、`src/db/pool.rs`、`tests/common/mod.rs`、`tests/test_db.rs`）
里 raw string 起手符出现次数**均为 0**（另 2 处在 `test_connect_retry.rs` 自身的文档注释里）。
所以 F-1 的**现实触发面确实为 0**，把它列为「已知且接受」在**结论上**是对的 ——
错的是那句「不会露出来」的技术断言，以及它没提「panic 这个失控面」。

**等长空格替换 / 偏移不变量 —— 核实成立。**
`mask_noncode` 每个分支要么推进 1 字节要么推进 2 字节且输出等长，长度严格守恒；
被屏蔽的多字节 UTF-8 整段变 ASCII 空格，不会切出半个字符（`String::from_utf8` 的 `.expect` 不会触发）。
`all_retry_loops`（`:965`）里 `body[body_open..body_open + masked_body.len()]`
的 `body_open` 取自 `masked`、`len` 取自 `masked_body`，两者同源 ⇒ 偏移一一对应。
**实证**：探针 P1 的报错信息打印的「实测循环体」是**原文**，含完整的
`/* outer /* inner */ sleep( */` 嵌套块注释，而判定全程跑在屏蔽视图上 ——
若偏移有偏差，打印出来的不可能是这段对齐的原文。

**`normalize()` 与 `mask_noncode` 的相互作用 —— 结论良性，但有一条副作用值得记。**
`normalize`（`:289-295`）先 trim 每行、**删空行与整行注释**、再 `join("\n")`。
它**确实改变相对原始文件的字节偏移**，但 `mask_noncode` 是在**归一化之后**的同一字符串上运行的，
后续所有偏移都同源，所以不变量不受影响。保留换行保证了行注释有可收尾边界 ——
这正是 `mask_noncode` 依赖的前提，两者一致，无冲突。
副作用：`normalize` **先于** `mask_noncode` 删掉整行注释 ⇒ `mask_noncode` 的「行注释」分支
在真实实参上几乎无事可做，真正干活的是行尾注释 / 块注释 / 字符串 / char。
这解释了我第一版 W5b 失败的机理（见 Q1）。另外，若将来报错要引用原始文件行号，
归一化会让行号错位 —— 当前 panic 只打印片段文本，无实际影响。

### Q4 「待办 vs 决策」判据成立吗？—— **方向合理，作为判据不成立**

判据原文在 `:37-40`。独立评估，三条反对理由：

1. **只用了一个维度，丢掉了修复成本。** 判据只看「触发是否自然」。
   后果就是 F-4：修复只要十余行（本 PR 自己刚用过同一手法），却因为「触发要造假函数」
   被归入决策。**低成本 + 已实测可利用**的洞被封掉，是这条判据最直接的反例。
2. **五条的「不自然程度」差异极大，却被当成同类。** F-3 需要定义 `fn Some` ——
   确实极不自然。而 C-4 只要把 helper 命名为 `raw_connect` —— 日常写法，不构造任何东西。
   **C-4 不满足这条判据**，却被一并算作「决策」。
3. **「需要刻意构造」在本仓已被反复跨过。** REQ-041 到 044 连续四轮，每轮 QA 都能构造出绕过
   （本轮我就构造出 25 条）。「要刻意构造」只说明**发现成本**高，
   而发现成本恰恰就是 QA 在做的事 —— 它不能作为「不会发生」的论据。

**建议（供 BA 参考，不必本轮执行）**：把判据改成二维 ——「自然度 × 修复成本」，
只有「既不自然、又难修」才封为决策；「不自然但好修」的应进待办。
按此重判：F-4（好修）⇒ 待办；C-4（自然触发）⇒ 待办；F-3 / F-1（难修）⇒ 决策成立。
