## 2. BL-3 顺序与列 —— 通过
```
[BL3-COLUMN] action_types.ordinal integer nullable=NO default=0     （information_schema 查得）
```
单连接 SET 切计划（连接池会串扰，故取单连接顺序执行 SET+查询）：
```
RESET ALL                                 order_by=[z,m,a]  no_order_by=[a,m,z]  EXPLAIN: Sort(Sort Key: ordinal) <- Index Scan using action_types_version_id_key_key
SET enable_indexscan=off                  order_by=[z,m,a]  no_order_by=[z,m,a]  EXPLAIN: Sort <- Bitmap Heap Scan
SET enable_seqscan=off                    order_by=[z,m,a]  no_order_by=[z,m,a]  EXPLAIN: Sort <- Bitmap Heap Scan
SET enable_indexscan=off; enable_seqscan=off  order_by=[z,m,a] no_order_by=[z,m,a] EXPLAIN: Sort <- Bitmap Heap Scan
SET enable_bitmapscan=off                 order_by=[z,m,a]  no_order_by=[a,m,z]  EXPLAIN: Sort <- Index Scan
```
关键：`no_order_by` 在默认计划下返回 **a→m→z**（走 unique(version_id,key) 索引），换 bitmap 计划又变回 z→m→a。
→ 证明缺陷期顺序确实由优化器当场决定；`ORDER BY ordinal` 后 5 种计划全部稳定为写入序 z→m→a。
重复读 5 次：[z,m,a] ×5。
