## 设计决定

1. **新建 `src/domain/model_view.rs`**（红线：建模轨投影不许写进 `view.rs`）。
   入口 `project_model_track(&Snapshot) -> ModelTrackView`，**纯函数、零 I/O**
   （不出现 `sqlx` / `PgStore` / `db::`，守住 domain 层 AC-002 纯度判据）。
2. **入参取 `&Snapshot` 而不是新造一份窄输入**：`SnapshotView` 只装
   customer view 要的字段，装不下 `extracted_by` / `action_types` / `functions`；
   照 `view.rs` 的「不是 Snapshot 的镜像」告诫再造一个近似镜像会更糟。
   `diff_snapshots` 也有取 `&Snapshot` 的先例。
3. **接到已有的 `--model-view` 通道上**（替换原始快照转储）——
   CLI 通道本来就有，缺的只是投影；domain 层保持零 I/O，投影可被别的层复用。
4. **分离靠「类型不同 + 通道不同」，不靠运行时开关**：
   `ModelTrackView` 与 `CustomerView` 是两个互不相干的类型，
   建模轨那一份**从不经过** `scan_modeling_terms`（它只扫客户视图）。

## 待报 BA 的实况问题（发现但未修）

- **P1（结构性）** `review decide --track model` 裁决的是**提案条目**，
  而本投影读的是**已落库快照**。两者不是同一个对象：
  FDE 在裁决提案时仍看不到该提案条目的建模细节。
  验收把数据源全部指向快照层，故本需求按快照做；提案侧的建模轨视图是**下一个缺口**。
- **P2** 快照层 `Property` 没有独立 `pk` 位，FDE 判主键只能从 `column` + `nullable` 推断。
  建模轨把 `column` 原样给出（这是快照层能给的全部），不伪造 `pk` 字段。
