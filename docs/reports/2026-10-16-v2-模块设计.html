01

分层与依赖方向

新增了 runtime/ 与 server/ 两层。依赖只能向下，两条禁止依赖用红色标出。

为什么推理层不能放 domain：它要发 SQL 和 HTTP，而 domain/ 的零 I/O 是可执行的验收条件，不是风格偏好。拆开之后，规则求值、SQL 生成、权限判定全在 domain（纯函数、可单测），只有「发出去」这一步在 runtime（可 mock）。
两条禁止依赖（会直接破坏现有验收）
① domain → runtime | db | server 任何一条 ⇒ grep -rn 'sqlx|PgStore|db::' src/domain/ 立刻有输出，AC-002 变红
② runtime → server ⇒ 编排层知道协议，会导致同一套推理既走 MCP 又走 HTTP 两条路径，两条都得测

关键接口定义

只给形状，不给实现。所有 domain 函数都是纯的 —— 这条是它们能被单测钉住的唯一原因。

// ── domain/rules.rs ─ 纯逻辑，无 I/O ──────────────────────
pub enum Rule {
    /// 从某类型的事实推导出另一类型的事实
    Traverse { from: Key, to: Key, via: Vec<LinkKey> },
    /// 过滤：只保留满足谓词的实例
    Filter   { on: Key, pred: Predicate },
    /// 聚合
    Aggregate{ on: Key, by: Agg },
}
pub enum Integrity { Complete, Partial, /// 查不到 ≠ 不存在 Unknown }

// 规则求值：纯函数。Err = 规则本身非法（不是「跑出错」）
pub fn eval(r: &Rule, ctx: &Facts) -> Result<Vec<Fact>>;

// ── domain/binding.rs ─ 绑定形状与解析 ──────────────────
pub enum ReadSpec {
    Sql { stmt: String, cols: Vec<String> },   // 参数化
    Api { method: Method, path: String, map: ParamMap },
}
pub fn resolve(bs: &Bindings, k: &Key) -> QuerySpec;
pub fn coverage(bs: &Bindings) -> Integrity;  // 部分源缺失 → Partial

// ── domain/sqlgen.rs ─ 生成即用，但生成是纯函数 ──────────
// 表/列白名单在此强制：不在白名单的标识符直接拒绝，不做任何转义兜底
pub fn build(s: &QuerySpec, wl: &Whitelist)
    -> Result<(String, Vec<Value>), GenError>;
pub enum GenError { UnknownTable(String), UnknownColumn(String), BadShape(String) }

// ── domain/authorization.rs ─ 权限判定 ────────────────────
pub enum Decision { Allow, /// 超出该操作人的授权范围 Deny(Reason), /// 该动作类型未声明任何绑定 NoBinding }
pub fn allow(op: &Operator, a: &Action, g: &Grants) -> Decision;

// ── domain/graph.rs ─ 给 user view 的图投影 ────────────────
pub struct GraphProjection { pub nodes: Vec<Node>, pub edges: Vec<Edge> }
pub fn project(v: &CustomerView) -> GraphProjection;
返回值里带 Integrity 是刻意的：调用方拿到的不是「一个列表」，而是「一个列表 + 这个列表能不能支撑『确定没有』」。D4 未定前，Integrity::Unknown 就是安全的默认。

推理层内部结构

以「客户 A 有多少条订阅」为例，看一次 reasoner 内部循环怎么走。

① ② ③ 全在 domain，全是纯函数 —— 意味着「规则写得对不对」「SQL 生成得安不安全」都能用构造样本单测，不需要连库、不需要 mock。只有 ④ 需要真实 I/O，也是唯一需要集成测试的一段。
这个切分就是纪律 G 的直接收益：变异证据可以在纯函数层做，条数多、复现快。
