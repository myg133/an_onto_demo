# ADR-005 · 决策点必须由 AI 先提案

- **日期**：2026-10-22
- **状态**：已接受（产品级原则）
- **提出者**：用户
- **原文**：「产品中，涉及到决策的，都先用 AI 来做提案。」
- **影响**：所有现有与未来的需求

## 背景

过去几轮的实践里，出现了一种**反模式**：AI 提案发生在**对话里**（我派子 agent 做），产出的文件被当成输入喂给产品。

| 决策点 | 谁在做 | 问题 |
| --- | --- | --- |
| 表名/属性名的中文名 | **对话里的子 agent**（`table_names.json` 记 `agent=ba-michael-20261021`） | 产品**有** `ontok-translate-names`（REQ-090），却没用它 |
| 哪些表不进本体 | 对话里 AI 逐张判（REQ-113 的做法） | 产品只接受 `--exclude` 文件，判断在产品外 |
| 对象如何分组 | 对话里 AI 语义分组（REQ-115 的做法） | 产品只有算法版 `concept suggest`，AI 语义版在对话里 |
| 审核建议 | 确定性推导（REQ-112） | 没有 AI 提案路径 |
| 文档断言 ↔ 表 的对齐 | 尚未实现 | — |

**后果**：溯源里写着「谁产的」，但那个"谁"是**对话里的临时 agent**，不是产品能力；换个用户跑同样的流程，拿不到同样的东西。**产品看起来能做本体，实际上一半的语义是人在对话里手工喂进去的。**

## 决策

**每一个「决策点」都必须有产品内置的 AI 提案路径。** 提案不是结果，是**可评审的候选**。

### 什么叫「决策点」

满足全部两条：

1. 需要**语义判断**（表结构、文档、业务常识），不是纯计算；
2. 结果会被**人签字**后才生效。

### 什么不是决策点（不需要 AI 提案）

| 类别 | 例子 | 为什么 |
| --- | --- | --- |
| 纯计算 | 置信度分数、sha256、计数闭合 | 确定性即可，AI 只会引入噪声 |
| 规则判定 | 发布闸、门禁、格式校验 | 判据必须可复现、可争辩 |
| 机械映射 | 列名 → 属性名（同义词表命中） | 查表即可，AI 反而更慢 |

### 提案的统一形状（硬要求）

```json
{
  "claim":      "这张表是「客户套餐订阅」",        // 判断本身
  "evidence":   ["表注释：用户套餐订阅表", "列：customer_id → customers"],  // 依据
  "confidence": 0.86,
  "reason":     "注释与列结构一致；名字 subscriptions 与注释同义",          // 为什么这么判
  "decided_by": "ai:<model>",                    // 谁提的
  "reviewed_by": null                             // 谁签的；null = 未签
}
```

**四条不可让步**：

| # | 规则 |
| --- | --- |
| **P1** | 提案必须**落盘**（文件或库），可 diff、可评审、可回滚 |
| **P2** | 提案**永远不权威**：未签字的提案不得进入快照 |
| **P3** | 必须**可复现**：指纹缓存（输入 hash + prompt_sha + model + agent_version） |
| **P4** | 必须**可溯源**：产物里能查到「这条用的是哪份提案、谁签的」 |

### 降级（允许，但要标明）

无模型 / 超预算时，允许确定性兜底（如算法分组、规则命名），但：

- 必须标 `source = "rule"`，⛔ 不得冒充 `ai`；
- 界面上必须能区分「AI 提的」与「规则算的」。

## 后果

### 正面

- 产品**自己**能产出语义，不再依赖「对话里有个聪明的 agent」；
- 每个决策有证据、有置信度、有签字人，可审计；
- 换人、换机器，跑同样的输入得到同样的提案（有缓存时逐字节一致）。

### 负面 / 代价

- **成本**：每个决策点都要调模型，必须配缓存与预算闸；
- **复杂度**：每个决策点都要一套「提案 → 评审 → 落地」的管路；
- **延迟**：审核界面要等提案生成。

### 对既有需求的处置

| 需求 | 处置 |
| --- | --- |
| REQ-113（排除表） | 产品只接受文件 ⇒ **要补 `exclude suggest`** |
| REQ-115（概念分组） | 产品只有算法 ⇒ **要补 AI 语义版** |
| REQ-112（审核建议） | 故意零模型 ⇒ **按本 ADR 需补 `--ai` 模式**（确定性版保留为降级） |
| REQ-116（文档断言） | 已经是 AI 提案（✅ 符合） |
| 表名（REQ-090） | 产品有能力但**流程里没用** ⇒ **接进主流程** |
