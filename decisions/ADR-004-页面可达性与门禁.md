# ADR-004 · 页面可达性与门禁（`/` 免 token 的取舍）

- **日期**：2026-10-21
- **状态**：已接受（REQ-110 实现）
- **相关**：REQ-093（只读图服务）· REQ-106（首页项目名注入）· REQ-107（出口收口）· REQ-110（本 ADR 的触发者）
- **代码落点**：`src/server/http.rs`（`build_router` / `require_token` / `index` / `get_scope`）· `src/server/page.rs`（`INDEX_HTML`）
- **改写（不是删除）**：REQ-093 的判据「未登录探测不到任何路径」

## 背景

REQ-093 的只读图服务把身份门 `require_token` 挂在**全局 layer** 上 —— 包括 `GET /` 这个**静态页面壳**。于是出现死循环：

- 要看到页面，得先有口令；
- 要填口令，得先看到页面；
- 而浏览器的导航请求**不可能**带 `Authorization: Bearer …` 头。

门禁的初衷写在 REQ-093 的判据里：「未登录连有哪些路径都探测不到」。这在「只给已持口令的人用」时成立；但产品一旦要「打开浏览器就能看到页面」，它就把页面本身锁死了。

## 决策

**`GET /` 免 token，`/api/*` 一律要 token。**

| 路由 | token | 内容 |
| --- | --- | --- |
| `GET /` | **免** | **静态页面壳**：HTML/CSS/JS 全内联，**不含任何本体数据**（无项目名、无版本号、无图、无对象名） |
| `GET /api/scope` | 必须 | 页面壳拿口令后问「看哪个项目、哪一版」 |
| `GET /api/graph` | 必须 | 整份客户视图（图） |
| `GET /api/node` | 必须 | 单个对象的属性与说明 |
| `GET /api/ontology.ttl` | 必须 | TTL 导出（页面「导出 TTL」按钮） |

实现要点：

1. `require_token` 从「全局 layer」改为**只加在 `/api` 子路由**上；
2. `/api` 子路由**自带 fallback**，且身份门排在 fallback **之前** ⇒ 未注册的 `/api/xxx` 无口令同样 **401**，`/api` 这一层的路径探测仍然探测不到；
3. `GET /` 的响应体与 `page::index_html()` **逐字节相同**（服务端不往里拼任何东西）；
4. 页面拿口令后先 `GET /api/scope`，再 `GET /api/graph` / `/api/node`；导出按钮走 `GET /api/ontology.ttl`。

## 取舍与代价（必须一起读）

| 得到 | 付出 |
| --- | --- |
| 浏览器能打开页面（口令框终于等得到人） | **服务存在性可被探测**：无口令的人知道「这里有个服务」 |
| 页面有「导出 TTL」按钮，不再靠手工脚本 | 多两条 gated 出口（H4 / H5），必须登记进 REQ-107 的 `OUTLETS` |
| 项目名出口从「首页整页」收窄到「`/api/scope` 一个 JSON」 | `/api/scope` 成为项目名的唯一回显点，必须过同一道发布闸 |

**没有付出的**（这是决策能被接受的关键）：

- 数据面**一个字节**都没有多放出去：`/api/graph` / `/api/node` / `/api/ontology.ttl` 无口令全部 401；
- 页面壳**不含任何数据**：用 `secretproj` / 第 7 版 / 含 `绝密对象` 的项目起服务，`GET /` grep 项目名 / 版本号 / 对象名 **0 命中**（AC-005）；
- 口令仍**不出现在**响应体、页面源码、日志、错误信息里（REQ-106 的既有判据全部保留）。

## 判据改写（不是删除）

REQ-093 的原判据 `unauthenticated_probes_cannot_discover_which_paths_exist` 改写为 `unauthenticated_probes_learn_nothing_but_the_shell_exists`：

| 请求 | 期望 | 理由 |
| --- | --- | --- |
| `GET /` | **200** | 静态壳，零数据 |
| `GET /api/…`（含**未注册**路径） | **401** | `/api` 这一层的路径探测仍然探测不到 |
| `POST /api/…` | **401**（不是 405） | 变更动词也不许泄露「这个 API 存不存在」 |

⛔ 测试是**改写**：`/api/*` 的每条断言都还在，只是 `/` 从「401」变成「200 且不含数据」。

## 被拒绝的方案

| 方案 | 为什么不行 |
| --- | --- |
| token 写进页面源码 | 等于把口令发给所有能打开页面的人；会进缓存、截图、git |
| token 放 URL query | 进浏览器历史、Referer、代理日志 |
| 只放开 `/api/graph` | 数据面直接公开，等于取消门禁 |
| 给浏览器一条「无 token 的壳数据接口」 | 把数据出口换个名字，门禁形同虚设 |
| Cookie + 登录页 | 需要会话/过期/吊销 —— 属 REQ-099，本轮不做 |

## 后果

- **正面**：页面可达；导出在产品内；项目名回显点从「整页 HTML」收窄成一个 gated JSON。
- **负面**：服务存在性可被探测（已接受）；`/` 从 401 变 200 是对 REQ-093 判据的**有意改写**，已同步改写测试并写本 ADR。
- **将来**：若需要「连服务存在性都藏起来」，正确做法是**前置一层反代/网关**做统一身份，而不是把静态壳再锁回去（那会让页面可达性重新变成死循环）。
