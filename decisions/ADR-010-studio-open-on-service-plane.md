# ADR-010 · Studio 进服务面并对客户开放（撤回 `serve` 的回环硬限制）

- 日期：2026-10-26
- 状态：**已接受**（用户拍板"进服务面，直接开放"）
- 关联：REQ-155

---

## 一 · 决策

把新 UI（**Studio**）做成**服务面**（`ontok`，进镜像）的一个页面，**直接对客户开放**（不是默认关闭）。

同时**撤回** `ontok serve` 原有的硬性约束：

```rust
// 旧（REQ-093）：
// 监听地址只允许回环（127.0.0.1 / ::1），绑别处直接拒绝启动。
```

---

## 二 · 为什么撤回这条（它是**故意**加的）

| 当时的理由 | 现在为什么不成立 |
| --- | --- |
| `serve` 是**只读图查看器**，定位是"FDE 本机看一眼" | 用户要求它变成**客户可见的产品页面** |
| 回环限制是"没有可写的地方"这条安全论证的一部分 | 该论证的前提是"只有本机"；开放后前提变了 |
| 没有开发模式开关（fail-closed） | 现在需要的是**正式鉴权**，不是"关闭" |

**结论**：不是"删掉一条碍事的检查"，而是**用正式鉴权替换一条物理隔离**。所以必须同时满足下面的补偿条件。

---

## 三 · 补偿条件（**缺一条就不许上线**）

| # | 条件 | 为什么 |
| --- | --- | --- |
| **C1** | **仍是只读**：只接受 `GET`，任何写类请求 `405` | 这是原设计最强的保证，必须保留 |
| **C2** | `/api/*` 一律要口令（`Authorization: Bearer`），**页面壳可免** | 与 `query serve` 同口径 |
| **C3** | 口令**不得短于 16 字符**，且**不从 URL 参数读**（只读 header） | 防日志/Referer 泄漏 |
| **C4** | 口令错/缺 ⇒ **401**，且响应体**不泄漏任何本体数据** | fail-closed |
| **C5** | 发布闸（脱敏）**不变**：客户视图仍是剔除技术用语后的版本 | 现在有 748 条属性说明被隐去，开放后更容易被观察，**不能放松** |
| **C6** | 绑非回环地址时，启动**必须打印醒目警告**（保留 `--allow-public` 这一步，但不再是拒绝） | 让运维看见"我正在对外开一个只读图" |

---

## 四 · 被否决的替代方案

| 方案 | 否决理由 |
| --- | --- |
| 默认关闭 + 开关 | 用户明确要"直接开放"；且默认关等于又造一个没人用的页面 |
| 独立静态站点（A 方案） | 要多打四场仗：新域名、CF 规则、CORS、鉴权同源。**CF WAF 已经咬过一次**（`403 error code: 1010`） |
| 保留回环 + 靠 port-forward 给客户 | 客户要的是浏览器直接打开，不是让我们代看 |

---

## 五 · 后果

| 项 | 影响 |
| --- | --- |
| `ontok serve --bind 0.0.0.0:x` | **从"拒绝启动"变成"启动 + 警告"**（行为变更，需在 `--help` 与验收里写明） |
| 镜像 | 多约 **76 KB** 静态资源（`include_str!`，不新增依赖） |
| 部署 | UAT 需要给 `serve` 加 ingress 路径（或并入现有 ingress） |
| 测试 | 新增：非回环绑定**能起**、401/405 行为、页面壳免口令但零数据 |
| 安全面 | **新增一个对外只读端点** —— 这是本次最大的风险项，靠 C1–C6 收敛 |

---

## 六 · 一句话

> **把"只有本机能看"换成"对外能看但只读且要口令"。**
> 物理隔离换成鉴权，所以鉴权那几条（C1–C6）就是新的隔离层，**一条都不能少**。

# ADR-010-A · 修订：Studio 挂 `query serve`，**不动 `ontok serve`**

- 日期：2026-10-26（同日修订）
- 状态：**已接受**（替代 ADR-010 §一/§三/§五 中关于 `ontok serve` 的部分）

## 一 · 为什么要修

原决定假设"Studio 替换 `ontok serve` 的页面壳，然后放开它的回环限制"。核代码后发现**前提不成立**：

| 事实 | 后果 |
| --- | --- |
| `src/service.rs:62`：`ontok serve` **只接受 GET**，写类请求一律 405 | Studio 的**查询台要 `POST /api/sparql`** ⇒ 放进去就破了它最强的安全保障（ADR-010 的 C1） |
| `query serve` 已有 `catalog` / `describe` / `sparql` / `ontology.ttl` / `health`，**且已公开、已 token 鉴权** | Studio 放这里 ⇒ **零新增接口** |
| Studio 样机的图是**前端从 `/api/catalog` 自己算**（30 类 / 34 关系） | **不需要 `/api/graph`**，也不需要给 `serve` 加数据端点 |

## 二 · 修订后的决定

| 项 | 原 | **改后** |
| --- | --- | --- |
| Studio 归属 | `ontok serve` | **`query serve`**（服务面、进镜像、已公开） |
| 新增路由 | `/studio` + 放开 serve 回环 | **只有 `/studio`、`/studio/studio.css`、`/studio/studio.js`** |
| `ontok serve` 的回环限制 | **撤回** | **保留原样**（它仍是本机只读工具） |
| 新增对外攻击面 | 一个只读端点 | **0**（只是在已有服务上加静态资源） |

## 三 · 补偿条件（从 C1–C6 收窄，剩下的都必须满足）

| # | 条件 | 为什么仍然必要 |
| --- | --- | --- |
| **S1** | `/studio` 与两个静态资源**只接受 GET**（`POST/PUT/DELETE` ⇒ 405） | 页面本身没有任何写能力 |
| **S2** | **页面壳零数据**：HTML/CSS/JS 是编译期常量，**不含任何本体内容**；数据一律经 `/api/*` 取 | 这是原 Portal 的 AC-005，值得保留——壳可以匿名拿，但拿了也没用 |
| **S3** | 口令**只进 `sessionStorage`**，⛔ 不进 URL、⛔ 不进 `localStorage` | 防 Referer / 日志泄漏 |
| **S4** | 无口令或口令错 ⇒ 页面显示"需要口令"，**不显示任何数据**，并在 `/api/*` 得 401 | fail-closed |
| **S5** | 脱敏闸（客户视图）**不变** | 开放后更容易被观察，不能放松 |
| **S6** | `/api/*` 的鉴权语义**一个字节不变** | Studio 不引入任何新的鉴权分支 |

## 四 · 后果

| 项 | 影响 |
| --- | --- |
| 镜像 | +约 76 KB 静态资源（`include_str!`），无新依赖 |
| `ontok serve` | **零改动**（回环限制、view token、GET-only 全部保留） |
| 部署 | **零改动**：`query serve` 已经在 ingress 后面 |
| 「UI 上线」 | 只要发镜像 ⇒ 客户就能打开 `/studio` |
| 测试 | 新增：`/studio` 200 且**壳里零数据**、写类请求 405、401 时不泄漏 |

## 五 · 一句话

> **不是"开放一个只读服务"，而是"在已经开放的服务上贴一张静态墙报"。**
> 攻击面没增加，所以原 ADR 里那套"物理隔离换鉴权"的论证也就不需要了。
