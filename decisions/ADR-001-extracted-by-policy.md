# ADR-001 · 新版本的 `extracted_by` 取值口径

---

## 背景

每个本体版本都记 `extracted_by`（哪个 agent、哪个版本、哪一轮、哪些组失败），
用于在 agent 升级后**解释 diff 的来源**（规格 §8.4）。

待定的是：**新版本的 `extracted_by` 取什么值？**

三种场景：
- **A 人工修订** —— v1 是 agent 抽的，客户提了改名/补属性的提案
- **B 新一轮抽取** —— agent 换了版本再抽一轮
- **C 混合提案** —— 既有新抽的条目、又有人改的条目

---

## 决策

> **`apply(proposal) → new_version` 时，`new_version.extracted_by` 原样取提案的 `extracted_by`。
> 提案没有该字段时记 `null`（表示人工修订）。**

不做「一律继承」，也不做「按场景分支」。

---

## 理由

| 场景 | 本决策的结果 |
| --- | --- |
| B 新一轮抽取 | ✅ 提案带 `X v2.4.0`，v2 就记 `X v2.4.0` —— **agent 升级可见** |
| A 人工修订 | ✅ 提案带 `agent: null`，v2 如实表示「这版有人工成分」 |
| C 混合 | ✅ 提案怎么声明就怎么记，不猜 |

**关键：演进链不由 `extracted_by` 承担。**
想查 v2 怎么来的，看 v1 自己的 `extracted_by` 即可 —— 版本之间的父子关系由 `seq` + 父版本承担。

---

## 被否掉的两个替代方案

| 方案 | 否掉原因 |
| --- | --- |
| **一律继承** base 的 `extracted_by` | 场景 B 失效 —— agent 换人不可见，diff 无法解释，**退回成规格 §8.4 想防的那个问题** |
| **按场景分支**（抽取走 A、人工走 B） | 需要判断「这条提案是抽的还是人写的」—— 而**提案自己知道**，不需要我们猜。多一套判断逻辑就多一处出错点 |

---

## 后果

1. `Snapshot.extracted_by: Option<ExtractedBy>` —— **可空**（这是三态之一，AC-010 往返测试要覆盖）
2. `Proposal` 必须自带 `extracted_by` 字段，缺省为 `None`
3. `apply` 不得推断、不得回退到 base 的值 —— **不猜**是本决策的核心
4. 收敛判定通过**相邻版本的 `extracted_by.version` 比对**判断 agent 是否中途换版（§7.1 约束 3）
5. `failed_groups` 从不继承 —— 每一轮独立记录
