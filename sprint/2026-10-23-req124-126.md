## 二 · 三个界面，三套凭证

```
ontok serve           客户视图（看图/看对象/导出 TTL）      —— 只读
ontok qeury serve     查询服务（/api/sparql + MCP）         —— query token，租户来自 token
ontok console serve   内部工作台（管理 API + 页面）          —— admin token
ontok portal serve    客户门户（四个端点 + 页面）            —— portal token，只能问预置问题
```

**⛔ 三套凭证互不复用**：`kind` 必须是 `admin` / `query` / `portal`，加载期双向互斥（拿 admin 表起门户 ⇒ 拒绝启动，反之亦然）。

## 三 · 本轮抓到的「看起来做完了、实际没守住」

> 这一类问题在过去几轮反复出现。本轮又抓到 5 个，全部在合并前修掉。

| # | 声称 | 变异后 | 根因 |
| --- | --- | --- | --- |
| 1 | 「`sql_echo` 就是执行的 SQL」 | 删掉 echo 里的注入条件 ⇒ **516 条全绿** | 没有任何测试断言 echo 内容 |
| 2 | 「泄漏测试通过」 | 缺环境时**静默 SKIP 且算 pass** | 最重要的判据依赖平时跑不到的环境 |
| 3 | 「只读会话 `transaction_read_only=on`」 | 那行是**硬编码字符串** | 假回执 |
| 4 | 「查询台会提示查询服务未接入」 | 实际提示**列管理端点**、403 时**清掉 token ⇒ 死循环** | 提示方向错 + 状态机错 |
| 5 | 「泄漏判据」 | 用**行值交集**，两边余额都为 0 时**假红** | 判据逻辑错（比没有判据更糟：会训练人「看到红就换数据」） |

**共同点**：都不是功能没写，而是**写完了没人能证明它在起作用**。

## 四 · 我本轮犯的错（记录在案）

| # | 错 | 教训 |
| --- | --- | --- |
| 1 | 把「租户口径」当业务问题去问用户 | **产品机制 / 项目声明 / 业务决定**三层要分开；代码里不许出现 `customer_id` 字面量 |
| 2 | 同一条修正**同时发给原 Dev 又新派一个** | 派单前查 `list_agents`；一个 worktree 同一时间只允许一个写者 |
| 3 | AC 里写死「TriplesMap=84 / joinCondition=72」 | 这些数**依赖快照是否带排除**；验收要用**自洽口径**（== 该快照的类数/边数） |
| 4 | 草稿问题里 `SELECT ?license` 投影实例 IRI、id 含表名 | **会同时泄漏项目名与表名**；是 Dev 发现并改成启动期拒绝条件 |
| 5 | 检查脚本打印「确认没有 NUL」但**不失败** | 检查不生效 = 没检查 |
